XYrminal — ユーザーガイド

XYrminal は、シリアル・TCP・UDP 経由でデバイスと通信するための マルチプロトコルターミナルです。クライアントまたはサーバーとして動作し、 ファイル転送、ライブグラフ描画、マクロ・シナリオスクリプトの実行、 トリガーによる部分文字列のハイライト、すべてのディスク保存が可能です。

1. タブの概要

  • COM — シリアルポート (RS-232、RS-485、USB-CDC)。
  • TCP Client — リモート TCP サーバーへの接続。
  • TCP Server — ローカルポートで待ち受け、多数のクライアントを 受け入れます。
  • UDP Client — 固定の host:port との送受信。
  • UDP Server — ローカルポートをバインドし、任意の相手から受信、 ブロードキャスト。

2. COM タブ

2.1 接続

  • ドロップダウンからポートを選択します。リストが古い場合は スキャン を押します。
  • 接続 でポートを開き、切断 で閉じます。
  • ポートが開いているとき：
    • DTR と RTS トグルは 2 本の出力ラインを制御します。 DTR は通常 MCU のリセットピンに、RTS は BOOT0 または bootloader 有効化ピンに接続されています。クリックすると ポートを開き直すことなくラインを反転できます。
    • 4 つの LED が入力ラインを示します：CD、RI、 DSR、CTS。緑 = ライン有効、暗色 = 無効。

2.2 シリアル設定

ボーレート、データビット、パリティ、ストップビット、フロー制御。 各コンボの一番下に、非標準値のための カスタム… 項目があります。

2.3 ターミナル設定

  • 自動スクロール — 新しいデータが届いたときに最下部へ ジャンプします。
  • タイムスタンプ — 各行の前に [HH:MM:SS.mmm] を 付けます。
  • 自動保存ログ — 現在のセッションを実行中に直接ファイルへ 書き込みます。
  • フォーマット — 受信バイトのデコード方法：
    • Raw：HEX、DEC、OCT、BIN。
    • テキスト：ASCII、UTF-8、UTF-16 LE、 UTF-16 BE、CP1251、CP1252、CP866、 KOI8-R、Latin-1、Shift-JIS、GB2312、 GBK。
    Raw モードでは、受信した各チャンクは即座に独立した行として 印刷されます。テキストモードでは、部分的な行は改行が来るか 50 ms の沈黙が続くまでバッファリングされ、末尾の改行がない データでも表示されます（Hercules スタイルのフラッシュ）。
  • グラフ — ライブグラフパネルを開きます（第 5 節参照）。
  • クリア — ターミナル表示を消去します。
  • ログを保存 — 現在のバッファを logs/ に 書き出します。

2.4 送信

  • テキストを入力し、Enter または 送信 を押します。 ↑ / ↓ で入力履歴を 閲覧できます。
  • HEX — 入力を 16 進バイトとして扱います（"AA BB CC" → 3 バイト）。HEX モードでは +CR と CR=CR+LF は無視 されます。
  • +CR — 行末を追加します。CR=CR+LF 付きなら CR+LF、そうでなければ CR のみ。
  • マクロ — 第 7 節参照。
  • ファイル転送 — 第 6 節参照。

3. TCP / UDP クライアントタブ

  • 接続 — リモートホスト / ポート、オプションのローカルバインド、 タイムアウト。
  • 接続を維持（TCP Client のみ）— ピアが切断した場合、ワーカーは 2 秒ごとに再試行を続け、再接続するか「切断」を押すまで続きます。
  • Ping — TCP connect() プローブで、PowerShell の Test-Connection と同じ統計：チェックで固定シリーズを実行、 開始で周期的な ping を開始、停止で終了。

4. TCP / UDP サーバータブ

  • TCP Server — 待ち受け、クライアント一覧、オプションの エコー、オプションの 全員にブロードキャスト、 個別または全ピアの切断。
  • UDP Server — バインド、任意の相手から受信、最後の送信者を 記憶、最後の相手 / 明示的なアドレス / 255.255.255.255 へ返信。
  • 受信データには [host:port] のプレフィックスが付きます。 サーバーイベント（[+]、[-]、待ち受け中、 停止）は専用の色を持ちます。

5. ライブグラフ

「ターミナル設定」で グラフ を押します。ターミナル領域が 2 分割され、左がテキスト、右がライブグラフになります。

  • 各行 = 1 変数：名前 + パースマーカー。名前は必須、 マーカーは任意。
    • マーカーあり（例：VREF=）：パーサーは受信 テキスト内でマーカーを探し、その直後の最初の数値を 読み取ります。
    • マーカーなし：パーサーは受信チャンク内のどこかにある 最初の数値を読み取ります。
  • 複数行 = 同じグラフ上の複数の線、それぞれが独自の色を持ちます。
  • 開始 でキャプチャを開始します。一時停止 / 再開 で データを失わずにキャプチャを凍結します。停止 でセッションを 終了しパネルを閉じます。
  • T-Mode — X 軸がサンプルインデックスではなく 秒前 に なります。新しいデータがなくてもグラフは連続的にスクロールします。
  • View — ウィンドウに表示するポイント数（インデックスモード） または秒数（T-Mode）。
  • Export CSV — すべての取得チャンネルを表計算ソフト向けの CSV ファイルに保存します： index,time_s,<チャンネル1>,<チャンネル2>,…。 欠落した末尾の値は空のセルになります。UTF-8 with BOM なので Excel がキリル文字のチャンネル名を正しく開けます。
  • グラフ上にマウスを置くと、正確な値のツールチップが表示されます。

6. ファイル転送

  • COM、TCP Client、UDP Client タブで利用可能です。
  • プロトコル：
    • Raw — ファイルを生のバイトブロックで送信します。 ブロック間遅延は設定可能。ブートローダー、イメージ、 コンフィグに最適。
    • XMODEM — 古典的な 128 バイトブロック、CRC-16、 ACK/NAK ハンドシェイク、ブロックごとに最大 10 回の 再試行。
    • YMODEM — XMODEM-1K で、最初のブロックがファイル名 + サイズ。STM32 / ESP / AVR ブートローダーの標準。
    • ZMODEM — まだ実装されていません。
  • ブロックサイズ、ブロック遅延、最大ファイルサイズは 設定 → 転送設定 で構成します。そこでは 最後に送信したファイルを記憶 を有効にして、次回起動時に パスとプロトコルを復元することもできます。
  • XMODEM / YMODEM / ZMODEM は UDP では利用できません。

7. マクロとシナリオ

各タブには 10 スロット M1…M10 があります。各スロットには プレーンマクロまたはシナリオスクリプトのいずれかを格納できます。

7.1 プレーンマクロ

  • 短いテキスト（または 16 進バイト）をワンクリックで送信します。
  • 各マクロは独自の +CR、CR=CR+LF、HEX フラグを 持ちます — 入力フィールドの上にあるものとは独立しています。
  • ボタンにマウスを置くと内容が表示されます。空のスロットは 無効です。

7.2 シナリオスクリプト (.xyscen)

1 行に 1 コマンドのシンプルな UTF-8 テキストファイルです。コマンド には 2 つのスタイルがあり、同一ファイル内で自由に混在できます：

スタイル A — フラット、1 行に 1 コマンド（元の構文、 完全にサポート継続）：

# コメント
// これもコメント
send "AT+RST\r\n"
send HEX "AA 55 01 FF"
wait 3000
expect "OK" 2000
expect_search "ERROR" 3000
assert_rx "READY"
log "こんにちは"
let x = 5
send "AT+SET=$x\r\n"

スタイル B — C 風のブロックを持つミニ言語（変数、式、 if/else、while、for）：

let id = 3
let ok = 0

for (let i = 0; i < id; i++) {
    send "AT+PING\r\n"
    if (expect("PONG", 2000)) {
        ok++
    } else {
        log "デバイス $i は応答なし"
    }
    wait 200
}

if (ok == id) {
    log "$id 台すべて OK"
} else {
    log "$ok / $id 台 OK"
}

両方のスタイルを混在できます。元の構文で書かれた古いスクリプトは 変更なしで動作し続けます。

7.3 コマンド完全リファレンス

データ送信

  • send "テキスト" — 文字列を送信 (UTF-8)。エスケープ： \r \n \t \\ \" \' \0 \xNN。
  • send HEX "AA 55 01 FF" — 旧エイリアス、生の 16 進 バイトを送信します。
  • send[ENC] "テキスト" — send と同じですが、 明示的なエンコーディングを使用します。対応 ENC：
    • Raw：HEX ("AA 55")、BIN ("10101010 01010101")、 DEC ("170 85")、OCT ("252 125")。
    • テキスト：UTF-8、ASCII、UTF-16LE、 UTF-16BE、CP1251、CP1252、CP866、 KOI8-R、Latin-1、Shift-JIS、GB2312、 GBK。
  • send_slow[ENC] "テキスト" ms — バイト単位で送信し、 バイト間に ms ミリ秒の遅延を入れます。遅い MCU UART 向け。 [ENC] なしの場合は UTF-8 を使用。

待機とチェック

  • wait ms — 指定ミリ秒のポーズ。
  • expect "テキスト" ms — 最大 ms の間、RX に テキスト が現れるのを待ちます。呼び出し以降に 受信したバイトのみが対象。タイムアウトでスクリプト失敗。
  • expect_search "テキスト" ms — 同様ですが、スクリプト 開始以来蓄積された全 RX バッファを検索します。待機を 始める前にデバイスが既にテキストを送っていた場合に便利。
  • assert_rx "テキスト" — テキスト が RX バッファ に既に存在するかチェックします。即時、待機なし。
  • 式形式（スタイル B）では expect(...)、 expect_search(...)、assert_rx(...) は ブール値を返し、失敗してもスクリプトを中断しません。 if (...) 内での使用に最適。

変数と出力

  • let 名前 = 値 — 変数を定義します。値は数値、引用符 付き文字列、または $他の変数（参照）。
  • 任意の文字列内で $名前 により変数の値を挿入できます： send "AT+SET=$id\r\n"。
  • log "テキスト" — [SCENARIO] テキスト と してターミナルに出力します。$var を展開します。
  • print 式 — 任意の式の値を出力します。

制御構造（スタイル B）

  • if (条件) { ... } else if (条件) { ... } else { ... }。
  • while (条件) { ... }。
  • for (初期化; 条件; ステップ) { ... }。
  • ループ内の break / continue。

演算子（スタイル B）

  • 算術：+ - * / %。
  • 比較：== != < > <= >=。
  • 論理：&& || !（短絡評価）。
  • インクリメント / デクリメント：x++、x--。
  • 複合代入：+= -= *= /= %=。

組み込み関数

expect("needle", ms) bool — 上記参照。
expect_search("needle", ms) bool — 上記参照。
assert_rx("needle") bool — RX バッファ全体を即座にチェック。
num_from_rx(marker) int — RX バッファ内の marker 直後の最初の数値。 marker が空なら全体の最初の数値。見つからなければ 0。 小数部は切り捨て（整数のみ）。
len(s) int — 文字列長。
num(s) int — 数値化；非数値は 0。
str(v) 文字列 — テキストに変換。
abs(n) int — 絶対値。
time_ms() int — スクリプト開始からのミリ秒。

7.4 実用的な例

# 温度を読んでファンを切り替える
send "AT+READ\r\n"

if (expect("OK", 2000)) {
    let t = num_from_rx("TEMP=")
    log "温度 = $t"
    if (t > 30) {
        send "AT+FAN=1\r\n"
    } else {
        send "AT+FAN=0\r\n"
    }
} else {
    log "デバイスが応答しません"
}

7.5 スロットの構成

  • 設定 → マクロを設定 → <タブ> で 10 行のダイアログが 開きます。各行：テキストフィールド + +CR + CR=CR+LF + HEX。
  • 上部のボタン：
    • シナリオを追加… — .xyscen ファイルと スロット番号を選択します。スロットのボタンが S# に なります。
    • シナリオをクリア — スロットをプレーンマクロに戻します。
  • 設定 → すべてのマクロをリセット → … で 1 つのタブまたは すべてのマクロを消去します。
  • シナリオの実行中は、すべてのマクロと入力行が無効化されます。 進行状況は [SCENARIO] … 行として、専用の色で 表示されます。

8. トリガー

各タブは、ターミナル出力内の部分文字列をカスタムの前景色と背景色で ハイライトできます。

  • 設定 → トリガーを設定 → <タブ> でダイアログが 開きます。
  • 各行：一致させるテキスト + 前景色スウォッチ + 背景色スウォッチ。
  • 一致は大文字小文字を区別しません。重複する場合は上の行が優先 されます。
  • タブごとに最大 50 個のトリガー。
  • トリガーは .xyrmc ログにも保存されるため、ブラウザで 同じハイライトがレンダリングされます。
  • 設定 → トリガーをリセット → <タブ> / すべて で 消去します。

9. ログ

  • ログを保存 — 現在のバッファをアプリの隣の logs/ に自動生成名で書き込みます。
  • ログを名前を付けて保存… — パスとフォーマットを選択：
    • .xyrm — プレーンな UTF-8 テキスト。
    • .xyrmc — インラインカラー付きの完全な HTML ドキュメント。 任意のブラウザで開くと、トリガーのハイライトを含め、 当時のターミナルを正確に再現できます。
  • ログを開く… — 以前に保存したログを開きます：
    • .xyrm — 現在のタブのターミナルに読み込まれます。
    • .xyrmc — 元の行間遅延でログを再生する 再生 / 一時停止 / 停止 ツールバー付きの別ビューア ウィンドウが開きます。
  • ログフォルダを開く — ファイルマネージャで logs/ を開きます。

10. 設定メニュー

テーマ 10 種類の内蔵パレット、OS に追従する「システム」、編集可能な 「カスタム…」、即座にランダムパレットを生成する「ランダム」。 カスタムパレットは QSettings に保存されます。
ターミナル文字色 各出力カテゴリを個別に色付け、または現在のテーマにリセット。 16 種類の名前付き色。すでに他のカテゴリで使われている色は 競合を避けるため無効化されています。
言語 実行中に UI 言語を切り替えます。英語、ロシア語、ベラルーシ語、 ドイツ語、フランス語、中国語、日本語、韓国語。
UI スケール 75% / 100% / 125% / 150%。フォント、パディング、コントロール サイズ、最小ウィンドウサイズをスケールします。選択は 記憶されます。
マクロを設定 タブごとに 10 個のマクロスロットを編集します。
すべてのマクロをリセット 1 つのタブまたはすべてのマクロを消去します。
トリガーを設定 タブごとのトリガーリストを編集します。
トリガーをリセット 1 つのタブまたはすべてのトリガーを消去します。
転送設定 ファイル転送のブロックサイズ / ブロック遅延 / 最大ファイル サイズ、および「最後に送信したファイルを記憶」。
保存形式 プレーンテキスト (.xyrm) またはカラー HTML (.xyrmc)。

11. 表示メニュー

  • 現在のタブの個々のグループを表示または非表示にします（接続、 シリアル設定、ターミナル設定、サーバー、Ping）。
  • すべて表示 — 現在のタブのすべてのグループを表示します。
  • すべて非表示 — 現在のタブのすべてのグループを非表示に します。

12. キーボードショートカット

  • Ctrl+F — ターミナル内で検索。
  • F3 / Shift+F3 — 次の / 前の一致。
  • Enter 送信入力欄 — 送信。
  • ↑ / ↓ 送信入力欄 — コマンド履歴。
  • Esc — 検索パネルを閉じる。

13. 記憶される内容

終了時に、アプリはウィンドウジオメトリ、アクティブタブ、COM 設定、 TCP / UDP 設定、ping 設定、ターミナルと送信のトグル、グループの 可視性、テーマ（カスタムパレットを含む）、UI スケール、言語、 ターミナル色、保存形式、すべてのマクロとすべてのトリガー、 「最後に送信したファイルを記憶」が有効な場合は最後に送信した ファイルパスを保存します。次回起動時にすべて復元されます。

14. テーマの概要

  • システム — OS の配色に従います（ダーク → Black、 ライト → White）。
  • Purple、Gray、White、Black、Beige — 単色パレット。アクセント（タブ、ボタン、グループタイトル、 ハイライト）はテーマ色を使用し、背景はその暗い色合いになります。 赤と緑の意味的ボタンはテーマに関係なく赤と緑のままです。
  • Turquoise-Orange、Graphite-Sand、Purple-Gold、 Coral-Mint、Navy-Crimson — 2 色パレット。 背景に 1 色目、アクセントに 2 色目を使用します。
  • カスタム… — ユーザー定義パレット。20 個のカラーロールを それぞれカラーピッカーで編集できます。ボタン：
    • Random — 調和のとれたランダムパレットを生成します。
    • Reset to defaults — 内蔵の紫に戻します。
  • ランダム（メニュー内） — ランダムなカスタムパレットを 即座に生成して適用します。
