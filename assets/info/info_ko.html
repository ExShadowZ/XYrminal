XYrminal — 사용자 안내서

XYrminal은 시리얼, TCP, UDP를 통해 장치와 통신하기 위한 다중 프로토콜 터미널입니다. 클라이언트 또는 서버로 동작하고, 파일을 전송하고, 실시간 그래프를 그리고, 매크로와 시나리오 스크립트를 실행하고, 트리거로 부분 문자열을 강조하고, 모든 것을 디스크에 저장할 수 있습니다.

1. 탭 개요

  • COM — 시리얼 포트 (RS-232, RS-485, USB-CDC).
  • TCP Client — 원격 TCP 서버에 연결.
  • TCP Server — 로컬 포트에서 수신하고 다수의 클라이언트를 받아들입니다.
  • UDP Client — 고정된 host:port와 송수신.
  • UDP Server — 로컬 포트를 바인드하고, 임의의 상대로부터 수신, 브로드캐스트.

2. COM 탭

2.1 연결

  • 드롭다운에서 포트를 선택합니다. 목록이 오래된 경우 검색을 누릅니다.
  • 연결은 포트를 열고, 연결 끊기는 닫습니다.
  • 포트가 열려 있을 때:
    • DTR과 RTS 토글은 두 개의 출력 라인을 제어합니다. DTR은 보통 MCU 리셋 핀에, RTS는 BOOT0 또는 bootloader 활성화 핀에 연결됩니다. 클릭하면 포트를 다시 열지 않고 라인을 뒤집을 수 있습니다.
    • 4개의 LED가 입력 라인을 표시합니다: CD, RI, DSR, CTS. 녹색 = 라인 활성, 어두움 = 비활성.

2.2 시리얼 설정

보드레이트, 데이터 비트, 패리티, 정지 비트, 흐름 제어. 각 콤보 하단에 비표준 값을 위한 사용자 지정… 항목이 있습니다.

2.3 터미널 설정

  • 자동 스크롤 — 새 데이터가 도착하면 맨 아래로 이동합니다.
  • 타임스탬프 — 각 줄 앞에 [HH:MM:SS.mmm]를 붙입니다.
  • 자동 저장 로그 — 현재 세션을 실행 중에 바로 파일로 기록합니다.
  • 형식 — 수신 바이트를 디코딩하는 방법:
    • 원시: HEX, DEC, OCT, BIN.
    • 텍스트: ASCII, UTF-8, UTF-16 LE, UTF-16 BE, CP1251, CP1252, CP866, KOI8-R, Latin-1, Shift-JIS, GB2312, GBK.
    원시 모드에서는 수신된 각 청크가 즉시 독립된 줄로 인쇄됩니다. 텍스트 모드에서는 부분 줄이 줄 바꿈이 오거나 50ms의 정적이 지날 때까지 버퍼링되며, 끝에 줄 바꿈이 없는 데이터도 화면에 표시됩니다(Hercules 스타일 flush).
  • 그래프 — 실시간 그래프 패널을 엽니다(5절 참조).
  • 지우기 — 터미널 보기를 지웁니다.
  • 로그 저장 — 현재 버퍼를 logs/에 저장합니다.

2.4 전송

  • 텍스트를 입력하고 Enter 또는 보내기를 누릅니다. ↑ / ↓로 입력 기록을 탐색합니다.
  • HEX — 입력을 16진수 바이트로 취급합니다("AA BB CC" → 3바이트). HEX 모드에서는 +CR과 CR=CR+LF가 무시됩니다.
  • +CR — 줄 끝을 추가합니다. CR=CR+LF와 함께면 CR+LF, 아니면 CR만.
  • 매크로 — 7절 참조.
  • 파일 전송 — 6절 참조.

3. TCP / UDP 클라이언트 탭

  • 연결 — 원격 호스트 / 포트, 선택적 로컬 바인드, 타임아웃.
  • 연결 유지(TCP Client만) — 피어가 연결을 끊으면 워커가 2초마다 재시도하여 다시 연결되거나 "연결 끊기"를 누를 때까지 계속합니다.
  • Ping — PowerShell의 Test-Connection과 동일한 통계를 가진 TCP connect() 프로브: 확인은 고정 시리즈를 실행하고, 시작은 주기적 ping을 시작하고, 정지는 종료합니다.

4. TCP / UDP 서버 탭

  • TCP Server — 수신 대기, 클라이언트 목록, 선택적 에코, 선택적 모두에게 브로드캐스트, 개별 또는 모든 피어 연결 끊기.
  • UDP Server — 바인드, 임의의 상대로부터 수신, 마지막 발신자 기억, 마지막 발신자 / 명시적 주소 / 255.255.255.255로 응답.
  • 수신 데이터에는 [host:port]가 접두사로 붙습니다. 서버 이벤트([+], [-], 수신 대기, 중지)는 전용 색상을 사용합니다.

5. 실시간 그래프

"터미널 설정"에서 그래프를 누릅니다. 터미널 영역이 두 개로 나뉘어 왼쪽은 텍스트, 오른쪽은 실시간 그래프가 됩니다.

  • 각 행 = 하나의 변수: 이름 + 파싱 마커. 이름은 필수, 마커는 선택입니다.
    • 마커가 있는 경우(예: VREF=): 파서는 수신 텍스트에서 마커를 찾아 그 뒤의 첫 번째 숫자를 읽습니다.
    • 마커가 없는 경우: 파서는 수신 청크의 어딘가에 있는 첫 번째 숫자를 읽습니다.
  • 여러 행 = 같은 그래프의 여러 곡선, 각각 고유한 색상.
  • 시작은 캡처를 시작합니다. 일시정지 / 재개는 데이터 손실 없이 캡처를 멈춥니다. 정지는 세션을 종료하고 패널을 닫습니다.
  • T-Mode — X축이 샘플 인덱스 대신 초 전이 됩니다. 새 데이터가 없어도 그래프가 계속 스크롤됩니다.
  • View — 창에 표시할 점 수(인덱스 모드) 또는 초(T-Mode).
  • Export CSV — 모든 캡처된 채널을 스프레드시트에 적합한 CSV 파일로 저장합니다: index,time_s,<채널1>,<채널2>,…. 누락된 마지막 값은 빈 셀로 남습니다. UTF-8 with BOM이라 Excel이 키릴 문자 채널 이름을 올바르게 엽니다.
  • 그래프 위로 마우스를 이동하면 정확한 값이 담긴 툴팁이 나타납니다.

6. 파일 전송

  • COM, TCP Client, UDP Client 탭에서 사용 가능합니다.
  • 프로토콜:
    • Raw — 파일을 원시 바이트 청크로 전송하며 청크 간 지연을 구성할 수 있습니다. 부트로더, 이미지, 구성 파일에 적합합니다.
    • XMODEM — 클래식 128바이트 블록, CRC-16, ACK/NAK 핸드셰이크, 블록당 최대 10회 재시도.
    • YMODEM — XMODEM-1K, 첫 블록에 파일 이름/크기 포함. STM32 / ESP / AVR 부트로더의 표준.
    • ZMODEM — 아직 구현되지 않았습니다.
  • 청크 크기, 청크 지연, 최대 파일 크기는 설정 → 전송 설정에서 구성합니다. 여기에서 마지막 전송 파일 기억을 활성화하면 다음 시작 시 경로와 프로토콜이 복원됩니다.
  • XMODEM / YMODEM / ZMODEM은 UDP에서 사용할 수 없습니다.

7. 매크로와 시나리오

각 탭에는 10개의 슬롯 M1…M10이 있습니다. 각 슬롯은 일반 매크로 또는 시나리오 스크립트를 담을 수 있습니다.

7.1 일반 매크로

  • 짧은 텍스트(또는 16진수 바이트)를 한 번의 클릭으로 전송합니다.
  • 각 매크로는 자체 +CR, CR=CR+LF, HEX 플래그를 가집니다 — 입력 필드 위의 것들과 독립적입니다.
  • 버튼 위로 마우스를 이동하면 페이로드가 표시됩니다. 빈 슬롯은 비활성화됩니다.

7.2 시나리오 스크립트 (.xyscen)

한 줄에 하나의 명령이 있는 간단한 UTF-8 텍스트 파일입니다. 명령은 두 가지 스타일이 있으며 같은 파일에서 자유롭게 섞을 수 있습니다:

스타일 A — 플랫, 한 줄에 하나의 명령(원래 구문, 완전 지원):

# 주석
// 주석도 가능
send "AT+RST\r\n"
send HEX "AA 55 01 FF"
wait 3000
expect "OK" 2000
expect_search "ERROR" 3000
assert_rx "READY"
log "안녕하세요"
let x = 5
send "AT+SET=$x\r\n"

스타일 B — C 스타일 블록을 가진 미니 언어(변수, 표현식, if/else, while, for):

let id = 3
let ok = 0

for (let i = 0; i < id; i++) {
    send "AT+PING\r\n"
    if (expect("PONG", 2000)) {
        ok++
    } else {
        log "장치 $i 응답 없음"
    }
    wait 200
}

if (ok == id) {
    log "$id 대 모두 OK"
} else {
    log "$ok / $id 대 OK"
}

두 스타일 모두 섞어 쓸 수 있습니다. 원래 구문으로 작성된 오래된 스크립트도 수정 없이 계속 동작합니다.

7.3 명령 전체 참조

데이터 전송

  • send "텍스트" — 문자열 전송 (UTF-8). 이스케이프: \r \n \t \\ \" \' \0 \xNN.
  • send HEX "AA 55 01 FF" — 옛 별칭, 원시 16진수 바이트를 전송합니다.
  • send[ENC] "텍스트" — send와 동일하지만 명시적 인코딩 사용. 지원 ENC:
    • 원시: HEX ("AA 55"), BIN ("10101010 01010101"), DEC ("170 85"), OCT ("252 125").
    • 텍스트: UTF-8, ASCII, UTF-16LE, UTF-16BE, CP1251, CP1252, CP866, KOI8-R, Latin-1, Shift-JIS, GB2312, GBK.
  • send_slow[ENC] "텍스트" ms — 바이트 단위로 전송하며 바이트 간 ms 밀리초 지연. 느린 MCU UART에 유용. [ENC]가 없으면 UTF-8 사용.

대기와 검사

  • wait ms — 지정된 밀리초만큼 일시정지.
  • expect "텍스트" ms — 최대 ms 동안 RX에 텍스트가 나타나기를 기다립니다. 호출 이후 수신된 바이트만 고려됩니다. 타임아웃 시 스크립트 실패.
  • expect_search "텍스트" ms — 동일하지만 스크립트 시작 이래 누적된 전체 RX 버퍼를 검색합니다. 대기 시작 전에 장치가 이미 텍스트를 보낸 경우에 유용.
  • assert_rx "텍스트" — 텍스트가 RX 버퍼에 이미 있는지 확인. 즉시, 대기 없음.
  • 표현식 형식(스타일 B)에서 expect(...), expect_search(...), assert_rx(...)는 부울을 반환하고 실패해도 스크립트를 중단하지 않습니다. if (...) 안에서 사용하기 좋습니다.

변수와 출력

  • let 이름 = 값 — 변수 정의. 값은 숫자, 따옴표로 묶인 문자열, 또는 $다른변수(참조).
  • 모든 문자열에서 $이름으로 변수 값을 삽입할 수 있습니다: send "AT+SET=$id\r\n".
  • log "텍스트" — [SCENARIO] 텍스트로 터미널에 출력. $var 확장 지원.
  • print 표현식 — 임의 표현식의 값을 출력.

제어 구조 (스타일 B)

  • if (조건) { ... } else if (조건) { ... } else { ... }.
  • while (조건) { ... }.
  • for (초기화; 조건; 단계) { ... }.
  • 루프 안의 break / continue.

연산자 (스타일 B)

  • 산술: + - * / %.
  • 비교: == != < > <= >=.
  • 논리: && || ! (단락 평가).
  • 증가 / 감소: x++, x--.
  • 복합 대입: += -= *= /= %=.

내장 함수

expect("needle", ms) bool — 위 참조.
expect_search("needle", ms) bool — 위 참조.
assert_rx("needle") bool — 전체 RX 버퍼를 즉시 검사.
num_from_rx(marker) int — RX 버퍼에서 marker 뒤의 첫 번째 숫자. marker가 비어 있으면 전체 버퍼의 첫 번째 숫자. 찾지 못하면 0. 소수부는 잘림(정수만).
len(s) int — 문자열 길이.
num(s) int — 숫자 파싱; 숫자가 아니면 0.
str(v) 문자열 — 값을 텍스트로 변환.
abs(n) int — 절대값.
time_ms() int — 스크립트 시작 이후 밀리초.

7.4 실용적인 예제

# 온도를 읽고 팬 전환
send "AT+READ\r\n"

if (expect("OK", 2000)) {
    let t = num_from_rx("TEMP=")
    log "온도 = $t"
    if (t > 30) {
        send "AT+FAN=1\r\n"
    } else {
        send "AT+FAN=0\r\n"
    }
} else {
    log "장치가 응답하지 않음"
}

7.5 슬롯 구성

  • 설정 → 매크로 구성 → <탭>은 10개의 행이 있는 대화 상자를 엽니다. 각 행: 텍스트 필드 + +CR + CR=CR+LF + HEX.
  • 상단의 버튼:
    • 시나리오 추가… — .xyscen 파일과 슬롯 번호를 선택합니다. 슬롯 버튼이 S#이 됩니다.
    • 시나리오 지우기 — 슬롯을 다시 일반 매크로로 되돌립니다.
  • 설정 → 모든 매크로 초기화 → …는 한 탭 또는 모든 탭의 매크로를 지웁니다.
  • 시나리오가 실행되는 동안 모든 매크로와 입력 줄이 비활성화됩니다. 진행 상황은 [SCENARIO] … 줄로 자체 색상으로 인쇄됩니다.

8. 트리거

각 탭은 터미널 출력의 부분 문자열을 사용자 정의 전경색과 배경색으로 강조할 수 있습니다.

  • 설정 → 트리거 구성 → <탭>은 대화 상자를 엽니다.
  • 각 행: 일치시킬 텍스트 + 전경색 스와치 + 배경색 스와치.
  • 일치는 대소문자를 구분하지 않습니다. 겹치는 경우 위쪽 행이 우선합니다.
  • 탭당 최대 50개의 트리거.
  • 트리거는 .xyrmc 로그에도 저장되어 브라우저가 동일한 강조 표시를 렌더링합니다.
  • 설정 → 트리거 초기화 → <탭> / 모두는 트리거를 지웁니다.

9. 로그

  • 로그 저장 — 현재 버퍼를 앱 옆의 logs/에 자동 생성된 이름으로 씁니다.
  • 다른 이름으로 로그 저장… — 경로와 형식을 선택합니다:
    • .xyrm — 일반 UTF-8 텍스트.
    • .xyrmc — 인라인 색상이 있는 전체 HTML 문서. 아무 브라우저에서나 열면 트리거 강조를 포함하여 당시 터미널을 정확히 볼 수 있습니다.
  • 로그 열기… — 이전에 저장한 로그를 엽니다:
    • .xyrm — 현재 탭의 터미널로 로드됩니다.
    • .xyrmc — 원래 줄 간 지연으로 로그를 재생하는 재생 / 일시정지 / 정지 도구 모음이 있는 별도 뷰어 창을 엽니다.
  • 로그 폴더 열기 — 파일 관리자에서 logs/를 엽니다.

10. 설정 메뉴

테마 10가지 내장 팔레트, OS를 따르는 "시스템", 편집 가능한 "사용자 지정…", 즉석에서 무작위 팔레트를 생성하는 "랜덤". 사용자 지정 팔레트는 QSettings에 저장됩니다.
터미널 텍스트 색상 각 출력 범주를 개별적으로 색칠하거나 현재 테마로 재설정합니다. 16가지 명명된 색상. 이미 다른 범주에서 사용 중인 색상은 충돌을 피하기 위해 비활성화됩니다.
언어 실행 중에 UI 언어를 전환합니다. 영어, 러시아어, 벨라루스어, 독일어, 프랑스어, 중국어, 일본어, 한국어.
UI 크기 75% / 100% / 125% / 150%. 글꼴, 패딩, 컨트롤 크기 및 최소 창 크기를 조정합니다. 선택은 기억됩니다.
매크로 구성 탭당 10개의 매크로 슬롯을 편집합니다.
모든 매크로 초기화 한 탭 또는 모든 탭의 매크로를 지웁니다.
트리거 구성 탭당 트리거 목록을 편집합니다.
트리거 초기화 한 탭 또는 모든 탭의 트리거를 지웁니다.
전송 설정 파일 전송의 청크 크기 / 청크 지연 / 최대 파일 크기, 그리고 "마지막 전송 파일 기억".
저장 형식 일반 텍스트(.xyrm) 또는 컬러 HTML (.xyrmc).

11. 보기 메뉴

  • 현재 탭의 개별 그룹을 표시하거나 숨깁니다(연결, 시리얼 설정, 터미널 설정, 서버, Ping).
  • 모두 표시 — 현재 탭의 모든 그룹을 표시합니다.
  • 모두 숨기기 — 현재 탭의 모든 그룹을 숨깁니다.

12. 키보드 단축키

  • Ctrl+F — 터미널에서 검색.
  • F3 / Shift+F3 — 다음 / 이전 일치.
  • Enter 전송 입력에서 — 보내기.
  • ↑ / ↓ 전송 입력에서 — 명령 기록.
  • Esc — 검색 패널을 닫습니다.

13. 기억되는 항목

종료 시 앱은 창 기하, 활성 탭, COM 설정, TCP / UDP 설정, ping 설정, 터미널 및 전송 토글, 그룹 가시성, 테마(사용자 지정 팔레트 포함), UI 크기, 언어, 터미널 색상, 저장 형식, 모든 매크로 및 모든 트리거, "마지막 전송 파일 기억"이 활성화된 경우 마지막으로 전송한 파일 경로를 저장합니다. 다음 시작 시 모두 복원됩니다.

14. 테마 개요

  • 시스템 — OS 색 구성표를 따릅니다(어두움 → Black, 밝음 → White).
  • Purple, Gray, White, Black, Beige — 단색 팔레트. 악센트(탭, 버튼, 그룹 제목, 강조 표시)는 테마 색을 사용하고 배경은 그 어두운 음영입니다. 빨간색과 녹색 의미 버튼은 테마에 관계없이 빨간색과 녹색으로 유지됩니다.
  • Turquoise-Orange, Graphite-Sand, Purple-Gold, Coral-Mint, Navy-Crimson — 2색 팔레트. 배경은 첫 번째 색을, 악센트는 두 번째 색을 사용합니다.
  • 사용자 지정… — 사용자 정의 팔레트. 20개의 색상 역할을 각각 색상 선택기로 편집합니다. 버튼:
    • Random — 조화로운 무작위 팔레트를 생성합니다.
    • Reset to defaults — 내장 보라색으로 돌아갑니다.
  • 랜덤(메뉴에서) — 무작위 사용자 지정 팔레트를 즉시 생성하고 적용합니다.
