XYrminal — Benutzerhandbuch

XYrminal ist ein Multi-Protokoll-Terminal für die Kommunikation mit Geräten über seriell, TCP und UDP. Es arbeitet als Client oder Server, überträgt Dateien, zeichnet Live-Diagramme, führt Makros und Szenarien aus, hebt Teilstrings mit Triggern hervor und speichert alles auf der Festplatte.

1. Tabs-Übersicht

  • COM — serieller Port (RS-232, RS-485, USB-CDC).
  • TCP Client — Verbindung zu einem entfernten TCP-Server.
  • TCP Server — auf einem lokalen Port lauschen, viele Clients.
  • UDP Client — Senden/Empfangen an einen festen host:port.
  • UDP Server — lokalen Port binden, Empfang von jedem, Broadcast.

2. COM-Tab

2.1 Verbindung

  • Port in der Liste wählen; Suchen drücken, wenn die Liste veraltet ist.
  • Verbinden öffnet den Port, Trennen schließt ihn.
  • Wenn der Port geöffnet ist:
    • DTR und RTS steuern die beiden Ausgangsleitungen. DTR ist üblicherweise mit dem Reset-Pin des MCU verbunden, RTS mit BOOT0 oder einem Bootloader-Enable-Pin. Ein Klick schaltet die Leitung um, ohne den Port neu zu öffnen.
    • Vier LEDs zeigen die Eingangsleitungen: CD, RI, DSR, CTS. Grün = Leitung aktiv, gedimmt = inaktiv.

2.2 Serielle Einstellungen

Baudrate, Datenbits, Parität, Stoppbits, Handshake. Jede Combo hat unten einen Eintrag Benutzerdefiniert… für Nicht-Standardwerte.

2.3 Terminal-Einstellungen

  • Auto-Scroll — springt nach unten, wenn neue Daten eintreffen.
  • Zeitstempel — Präfix [HH:MM:SS.mmm] vor jeder Zeile.
  • Auto-Speichern — die aktuelle Sitzung wird während des Betriebs direkt in eine Datei geschrieben.
  • Format — wie eingehende Bytes dekodiert werden:
    • Raw: HEX, DEC, OCT, BIN.
    • Text: ASCII, UTF-8, UTF-16 LE, UTF-16 BE, CP1251, CP1252, CP866, KOI8-R, Latin-1, Shift-JIS, GB2312, GBK.
    In Raw-Modi wird jeder empfangene Block sofort als eigenständige Zeile ausgegeben. In Text-Modi werden Teilzeilen gepuffert, bis ein Zeilenumbruch eintrifft oder 50 ms Stille vergehen — Daten ohne abschließendes Newline werden trotzdem angezeigt (Hercules-Style-Flush).
  • Diagramm — Live-Diagramm-Panel öffnen (siehe Abschnitt 5).
  • Leeren — Terminalausgabe löschen.
  • Protokoll speichern — Puffer nach logs/ schreiben.

2.4 Senden

  • Text eingeben, Enter oder Senden drücken. ↑ / ↓ — Verlauf.
  • HEX — Eingabe als Hex-Bytes interpretieren ("AA BB CC" → 3 Bytes). Im HEX-Modus werden +CR und CR=CR+LF ignoriert.
  • +CR — Zeilenende anhängen. Mit CR=CR+LF wird daraus CR+LF, sonst nur CR.
  • Makros — siehe Abschnitt 7.
  • Dateiübertragung — siehe Abschnitt 6.

3. TCP / UDP-Client-Tabs

  • Verbindung — Remote-Host / -Port, optionaler lokaler Bind, Timeout.
  • Verbindung halten (nur TCP Client) — wenn der Peer die Verbindung fallen lässt, versucht der Worker alle 2 Sekunden erneut, bis er sich wieder verbindet oder Sie „Trennen“ drücken.
  • Ping — TCP-connect()-Prüfung mit denselben Statistiken wie PowerShells Test-Connection: Prüfen startet eine feste Serie, Start startet ein periodisches Ping, Stopp beendet es.

4. TCP / UDP-Server-Tabs

  • TCP Server — lauschen, Client-Liste, optionales Echo, optionales Broadcast an alle, einzelnen oder alle Peers trennen.
  • UDP Server — bind, Empfang von jedem, letzten Absender merken, an letzteren / an explizite Adresse / an 255.255.255.255 antworten.
  • Eingehende Daten erhalten ein Präfix [host:port]. Server-Ereignisse ([+], [-], lauschend, gestoppt) haben eine eigene Farbe.

5. Live-Diagramm

Diagramm in „Terminal-Einstellungen“ drücken. Der Terminal- Bereich teilt sich in zwei: Text links, Live-Diagramm rechts.

  • Jede Zeile = eine Variable: Name + Parser-Marker. Name erforderlich, Marker optional.
    • Mit Marker (z. B. VREF=): der Parser sucht den Marker im eingehenden Text und liest die erste Zahl danach.
    • Ohne Marker: der Parser liest die erste Zahl irgendwo im eingehenden Block.
  • Mehrere Zeilen = mehrere Linien im selben Diagramm, jede mit eigener Farbe.
  • Start beginnt die Erfassung. Pause / Fortsetzen friert die Erfassung ohne Datenverlust ein. Stopp beendet die Sitzung und schließt das Panel.
  • T-Mode — die X-Achse wird zu Sekunden zurück statt Sample-Index. Das Diagramm scrollt kontinuierlich auch ohne neue Daten.
  • View — wie viele Punkte (Index-Modus) oder Sekunden (T-Mode) im Fenster sichtbar sind.
  • Export CSV — alle erfassten Kanäle als tabellenkalkulationsfreundliche CSV-Datei speichern: index,time_s,<kanal1>,<kanal2>,…. Fehlende Werte am Ende bleiben als leere Zellen. UTF-8 mit BOM, damit Excel kyrillische Kanalnamen korrekt öffnet.
  • Mit der Maus über das Diagramm fahren, um einen Tooltip mit dem genauen Wert zu sehen.

6. Dateiübertragung

  • Verfügbar in den Tabs COM, TCP Client und UDP Client.
  • Protokolle:
    • Raw — Datei als Rohbyte-Blöcke mit konfigurierbarer Zwischenblock-Verzögerung. Gut für Bootloader, Images, Konfigs.
    • XMODEM — klassische 128-Byte-Blöcke mit CRC-16, ACK/NAK-Handshake, bis zu 10 Wiederholungen pro Block.
    • YMODEM — XMODEM-1K mit einem ersten Block „Dateiname + Größe“. Standard für STM32 / ESP / AVR Bootloader.
    • ZMODEM — noch nicht implementiert.
  • Blockgröße, Blockverzögerung und maximale Dateigröße werden in Einstellungen → Übertragungseinstellungen konfiguriert. Dort kann auch Zuletzt gesendete Datei merken aktiviert werden, damit Pfad und Protokoll beim nächsten Start wiederhergestellt werden.
  • XMODEM / YMODEM / ZMODEM sind über UDP nicht verfügbar.

7. Makros und Szenarien

Jeder Tab hat 10 Slots, M1…M10. Jeder Slot kann entweder ein einfaches Makro oder ein Szenario-Skript enthalten.

7.1 Einfaches Makro

  • Kurzer Text (oder Hex-Bytes), per Klick gesendet.
  • Jedes Makro hat eigene +CR, CR=CR+LF und HEX Flags — unabhängig von denen über dem Eingabefeld.
  • Über die Schaltfläche fahren, um die Nutzlast zu sehen. Leere Slots sind deaktiviert.

7.2 Szenario-Skript (.xyscen)

Eine einfache UTF-8-Textdatei mit einem Befehl pro Zeile. Befehle gibt es in zwei Stilen, die im selben File frei gemischt werden können:

Stil A — flach, ein Befehl pro Zeile (die ursprüngliche Syntax, weiterhin voll unterstützt):

# Kommentar
// auch ein Kommentar
send "AT+RST\r\n"
send HEX "AA 55 01 FF"
wait 3000
expect "OK" 2000
expect_search "ERROR" 3000
assert_rx "READY"
log "hallo"
let x = 5
send "AT+SET=$x\r\n"

Stil B — Mini-Sprache mit C-artigen Blöcken (Variablen, Ausdrücke, if/else, while, for):

let id = 3
let ok = 0

for (let i = 0; i < id; i++) {
    send "AT+PING\r\n"
    if (expect("PONG", 2000)) {
        ok++
    } else {
        log "Gerät $i antwortete nicht"
    }
    wait 200
}

if (ok == id) {
    log "alle $id ok"
} else {
    log "$ok / $id ok"
}

Beide Stile lassen sich mischen. Alte Skripte in der ursprünglichen Syntax funktionieren unverändert weiter.

7.3 Befehlsreferenz

Daten senden

  • send "Text" — Zeichenkette senden (UTF-8). Escapes: \r \n \t \\ \" \' \0 \xNN.
  • send HEX "AA 55 01 FF" — alter Alias, sendet rohe Hex-Bytes.
  • send[ENC] "Text" — wie send, aber mit expliziter Kodierung. Unterstützte ENC:
    • Raw: HEX ("AA 55"), BIN ("10101010 01010101"), DEC ("170 85"), OCT ("252 125").
    • Text: UTF-8, ASCII, UTF-16LE, UTF-16BE, CP1251, CP1252, CP866, KOI8-R, Latin-1, Shift-JIS, GB2312, GBK.
  • send_slow[ENC] "Text" ms — Byte für Byte mit Verzögerung ms zwischen den Bytes. Für langsame MCU-UARTs. Ohne [ENC] wird UTF-8 verwendet.

Warten und Prüfen

  • wait ms — Pause für die angegebene Anzahl Millisekunden.
  • expect "Text" ms — bis zu ms auf Text in RX warten. Nur Bytes nach dem Aufruf werden berücksichtigt. Bei Timeout schlägt das Skript fehl.
  • expect_search "Text" ms — wie oben, aber sucht im gesamten seit Skriptstart gesammelten RX-Puffer. Nützlich, wenn das Gerät den Text schon vor dem Warten gesendet hat.
  • assert_rx "Text" — prüfen, dass Text bereits im RX-Puffer liegt. Sofort, ohne Warten.
  • In Ausdrucksform (Stil B) liefern expect(...), expect_search(...) und assert_rx(...) einen Bool und brechen das Skript bei Misserfolg nicht ab. Ideal für if (...).

Variablen und Ausgabe

  • let name = wert — Variable definieren. Wert kann eine Zahl, ein String in Anführungszeichen oder $andere (Referenz) sein.
  • In jedem String kann $name verwendet werden, um den Wert einer Variable einzusetzen: send "AT+SET=$id\r\n".
  • log "Text" — Zeile als [SCENARIO] Text ins Terminal drucken. Interpoliert $var.
  • print Ausdruck — Wert eines beliebigen Ausdrucks drucken.

Kontrollfluss (Stil B)

  • if (Bedingung) { ... } else if (Bedingung) { ... } else { ... }.
  • while (Bedingung) { ... }.
  • for (init; cond; step) { ... }.
  • break / continue innerhalb von Schleifen.

Operatoren (Stil B)

  • Arithmetik: + - * / %.
  • Vergleich: == != < > <= >=.
  • Logik: && || ! (mit Kurzschluss).
  • Inkrement / Dekrement: x++, x--.
  • Zusammengesetzte Zuweisung: += -= *= /= %=.

Eingebaute Funktionen

expect("needle", ms) bool — siehe oben.
expect_search("needle", ms) bool — siehe oben.
assert_rx("needle") bool — sofortige Prüfung des gesamten RX-Puffers.
num_from_rx(marker) int — erste Zahl nach marker im RX-Puffer. Leerer marker → erste Zahl im gesamten Puffer. 0 bei Nichtfund. Nachkommateil wird abgeschnitten (nur int).
len(s) int — Länge einer Zeichenkette.
num(s) int — Zahl parsen; 0, wenn nicht numerisch.
str(v) string — Wert in Text umwandeln.
abs(n) int — Absolutwert.
time_ms() int — Millisekunden seit Skriptstart.

7.4 Realistisches Beispiel

# Temperatur lesen und Lüfter umschalten
send "AT+READ\r\n"

if (expect("OK", 2000)) {
    let t = num_from_rx("TEMP=")
    log "Temperatur = $t"
    if (t > 30) {
        send "AT+FAN=1\r\n"
    } else {
        send "AT+FAN=0\r\n"
    }
} else {
    log "Gerät hat nicht geantwortet"
}

7.5 Slots konfigurieren

  • Einstellungen → Makros konfigurieren → <Tab> öffnet einen Dialog mit 10 Zeilen: Textfeld + +CR + CR=CR+LF + HEX.
  • Schaltflächen oben:
    • Szenario hinzufügen… — eine .xyscen-Datei und eine Slot-Nummer wählen. Die Slot-Schaltfläche wird zu S#.
    • Szenario entfernen — den Slot wieder in ein einfaches Makro umwandeln.
  • Einstellungen → Alle Makros zurücksetzen → … löscht Makros eines Tabs oder aller auf einmal.
  • Während ein Szenario läuft, sind alle Makros und die Eingabezeile deaktiviert. Der Fortschritt wird als [SCENARIO] …-Zeilen in eigener Farbe ausgegeben.

8. Trigger

Jeder Tab kann Teilstrings in der Terminalausgabe mit benutzerdefinierter Text- und Hintergrundfarbe hervorheben.

  • Einstellungen → Trigger konfigurieren → <Tab> öffnet einen Dialog.
  • Jede Zeile: Text zum Abgleich + Vordergrund-Swatch + Hintergrund-Swatch.
  • Abgleich ist Groß-/Kleinschreibung-unabhängig; obere Zeilen gewinnen bei Überlappung.
  • Bis zu 50 Trigger pro Tab.
  • Trigger werden auch in .xyrmc-Protokollen gespeichert, damit ein Browser dieselbe Hervorhebung rendert.
  • Einstellungen → Trigger zurücksetzen → <Tab> / Alle löscht sie.

9. Protokolle

  • Protokoll speichern — aktuellen Puffer in logs/ neben der App mit automatisch generiertem Namen speichern.
  • Protokoll speichern unter… — Pfad und Format wählen:
    • .xyrm — reiner UTF-8-Text.
    • .xyrmc — vollständiges HTML-Dokument mit Inline-Farben. In jedem Browser öffnen, um das Terminal exakt wie zuvor zu sehen, inklusive Trigger-Hervorhebungen.
  • Protokoll öffnen… — ein zuvor gespeichertes Protokoll öffnen:
    • .xyrm — in das Terminal des aktuellen Tabs geladen.
    • .xyrmc — öffnet ein separates Viewer-Fenster mit Play / Pause / Stop-Toolbar, das das Protokoll mit den ursprünglichen Zeilenabständen wiedergibt.
  • Protokollordner öffnen — logs/ im Dateimanager öffnen.

10. Einstellungsmenü

Design 10 eingebaute Paletten, „System“ (folgt dem OS-Schema), „Benutzerdefiniert…“ (eigener Paletteneditor) und „Zufällig“ (sofortige Erzeugung einer Zufallspalette). Benutzerdefinierte Paletten werden in QSettings gespeichert.
Textfarbe des Terminals Jede Ausgabekategorie einzeln einfärben oder auf das aktuelle Design zurücksetzen. 16 benannte Farben. Eine Farbe, die bereits von einer anderen Kategorie verwendet wird, ist deaktiviert, um Konflikte zu vermeiden.
Sprache Die Oberflächensprache im laufenden Betrieb umschalten. Englisch, Russisch, Belarussisch, Deutsch, Französisch, Chinesisch, Japanisch, Koreanisch.
UI-Skalierung 75 % / 100 % / 125 % / 150 %. Skaliert Schriften, Abstände, Steuerelementgrößen und die minimale Fenstergröße. Die Auswahl wird gespeichert.
Makros konfigurieren Die 10 Makro-Slots pro Tab bearbeiten.
Alle Makros zurücksetzen Makros eines Tabs oder aller auf einmal löschen.
Trigger konfigurieren Die Trigger-Liste pro Tab bearbeiten.
Trigger zurücksetzen Trigger eines Tabs oder aller auf einmal löschen.
Übertragungseinstellungen Blockgröße / Blockverzögerung / maximale Dateigröße für die Dateiübertragung, plus „Zuletzt gesendete Datei merken“.
Speicherformat Reiner Text (.xyrm) oder farbiges HTML (.xyrmc).

11. Ansicht-Menü

  • Einzelne Gruppen des aktuellen Tabs ein- oder ausblenden (Verbindung, Serielle Einstellungen, Terminal-Einstellungen, Server, Ping).
  • Alle anzeigen — alle Gruppen des aktuellen Tabs anzeigen.
  • Alle ausblenden — alle Gruppen des aktuellen Tabs ausblenden.

12. Tastaturkürzel

  • Ctrl+F — im Terminal suchen.
  • F3 / Shift+F3 — nächster / vorheriger Treffer.
  • Enter im Sende-Eingabefeld — senden.
  • ↑ / ↓ im Sende-Eingabefeld — Befehlsverlauf.
  • Esc — Suchfeld schließen.

13. Was gespeichert wird

Beim Beenden speichert die App Fenstergeometrie, aktiven Tab, COM-Einstellungen, TCP / UDP-Einstellungen, Ping-Einstellungen, Terminal- und Sende-Toggles, Gruppensichtbarkeit, Design (inklusive benutzerdefinierter Palette), UI-Skalierung, Sprache, Terminalfarben, Speicherformat, alle Makros und alle Trigger sowie den zuletzt gesendeten Dateipfad, wenn „Zuletzt gesendete Datei merken“ aktiviert ist. Beim nächsten Start wird alles wiederhergestellt.

14. Designs-Übersicht

  • System — folgt dem OS-Farbschema (dunkel → Black, hell → White).
  • Purple, Gray, White, Black, Beige — Einfarbige Paletten. Akzente (Tabs, Schaltflächen, Gruppentitel, Hervorhebungen) verwenden die Designfarbe, Hintergründe sind ein dunkler Ton davon. Rote und grüne semantische Schaltflächen bleiben unabhängig vom Design rot und grün.
  • Turquoise-Orange, Graphite-Sand, Purple-Gold, Coral-Mint, Navy-Crimson — Zweifarbige Paletten. Der Hintergrund verwendet die erste Farbe, Akzente die zweite.
  • Benutzerdefiniert… — benutzerdefinierte Palette. Jede der 20 Farbrollen über einen Farbwähler bearbeiten. Schaltflächen:
    • Random — erzeugt eine harmonische Zufallspalette.
    • Reset to defaults — zurück zum eingebauten Violett.
  • Zufällig (im Menü) — erzeugt und wendet sofort eine zufällige benutzerdefinierte Palette an.
