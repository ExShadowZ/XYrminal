XYrminal — user guide

XYrminal is a multi-protocol terminal for talking to devices over serial, TCP and UDP. It can act as a client or a server, transfer files, plot live data, run macros and scenario scripts, highlight substrings with triggers, and save everything to disk.

1. Tabs overview

  • COM — serial port (RS-232, RS-485, USB-CDC).
  • TCP Client — connect to a remote TCP server.
  • TCP Server — listen on a local port, accept many clients.
  • UDP Client — send/receive to a fixed remote host:port.
  • UDP Server — bind a local port, receive from anyone, broadcast.

2. COM tab

2.1 Connecting

  • Pick a port in the dropdown; press Scan if the list is stale.
  • Connect opens the port, Disconnect closes it.
  • When the port is open:
    • DTR and RTS toggles drive the two output lines. DTR is usually wired to the MCU reset pin; RTS to BOOT0 or a bootloader-enable pin. Clicking them flips the line without reopening the port.
    • Four LEDs show input lines: CD, RI, DSR, CTS. Green = line active, dim = inactive.

2.2 Setting serial

Baud rate, data bits, parity, stop bits, flow control. Every combo has a Custom… entry at the bottom for non-standard values.

2.3 Setting terminal

  • AutoScroll — jump to the bottom when new data arrives.
  • Timestamps — prefix every line with [HH:MM:SS.mmm].
  • Auto-save log — write the current session straight into a file as it happens.
  • Format — how incoming bytes are decoded:
    • Raw: HEX, DEC, OCT, BIN.
    • Text: ASCII, UTF-8, UTF-16 LE, UTF-16 BE, CP1251, CP1252, CP866, KOI8-R, Latin-1, Shift-JIS, GB2312, GBK.
    In raw modes each received chunk is printed immediately as a standalone line. In text modes partial lines are buffered until a newline arrives, or 50 ms of silence pass — data without trailing newlines still gets displayed (Hercules-style flush).
  • Plot — open the live plot panel (see section 5).
  • Clear — wipe the terminal view.
  • Save log — dump the current buffer to logs/.

2.4 Transmit

  • Type text, press Enter or Send. ↑ / ↓ browse the input history.
  • HEX — treat the input as hex bytes ("AA BB CC" → 3 bytes). In HEX mode +CR and CR=CR+LF are ignored.
  • +CR — append a line ending. With CR=CR+LF it becomes CR+LF, otherwise just CR.
  • Macros — see section 7.
  • File transfer — see section 6.

3. TCP / UDP client tabs

  • Connecting — remote host / port, optional local bind, timeout.
  • Keep connection (TCP client only) — if the peer drops the link, the worker keeps trying every 2 seconds until it reconnects or you press Disconnect.
  • Ping — TCP connect() probe with the same statistics as PowerShell's Test-Connection: Check runs a fixed series, Start runs a periodic ping, Stop ends it.

4. TCP / UDP server tabs

  • TCP Server — listen, list clients, optional Echo, optional Broadcast to all, disconnect one or all peers.
  • UDP Server — bind, receive from anyone, remember last sender, reply to last / to explicit address / broadcast to 255.255.255.255.
  • Incoming data is prefixed with [host:port]. Server events ([+], [-], listening, stopped) use a dedicated color.

5. Live plot

Press Plot in Setting terminal. The terminal area splits in two: text on the left, live plot on the right.

  • Each row = one variable: Name + Parser marker. Name is required; marker is optional.
    • With marker (e.g. VREF=): the parser searches incoming text for the marker and reads the first number after it.
    • Without marker: the parser reads the first number anywhere in the incoming chunk.
  • Multiple rows = multiple lines on the same plot, each with its own color.
  • Start begins capture. Pause / Resume freezes capture without dropping data. Stop ends the session and closes the plot panel.
  • T-Mode — X axis becomes seconds ago instead of sample index. The plot scrolls continuously even without new data.
  • View — how many points (index mode) or seconds (T-Mode) are shown in the window.
  • Export CSV — save all captured channels to a spreadsheet-friendly CSV file: index,time_s,<channel1>,<channel2>,…. Missing tail values are left as empty cells. UTF-8 with BOM, so Excel opens Cyrillic channel names correctly.
  • Hover the plot to see a small tooltip with the exact value.

6. File transfer

  • Available in COM, TCP Client and UDP Client tabs.
  • Protocols:
    • Raw — send the file as raw byte chunks with a configurable inter-chunk delay. Good for bootloaders, images, configs.
    • XMODEM — classic 128-byte blocks with CRC-16, ACK/NAK handshake, up to 10 retries per block.
    • YMODEM — XMODEM-1K with a filename/size block first. Standard for STM32 / ESP / AVR bootloaders.
    • ZMODEM — not implemented yet.
  • Chunk size, chunk delay and max file size are configured in Setting → Transfer settings. There you can also enable Remember last sent file path so the file path and protocol are restored on the next launch.
  • XMODEM / YMODEM / ZMODEM are not available over UDP.

7. Macros and scenarios

Every tab has 10 slots, M1…M10. Each slot can hold either a plain macro or a scenario script.

7.1 Plain macro

  • Short text (or hex bytes) sent with one click.
  • Each macro has its own +CR, CR=CR+LF and HEX flags — independent of the ones above the input field.
  • Hover a button to see its payload. Empty slots are disabled.

7.2 Scenario script (.xyscen)

A plain UTF-8 text file with one command per line. Commands come in two styles, freely mixable in the same file:

Style A — plain, one command per line (matches the original syntax and is still fully supported):

# comment
// also a comment
send "AT+RST\r\n"
send HEX "AA 55 01 FF"
wait 3000
expect "OK" 2000
expect_search "ERROR" 3000
assert_rx "READY"
log "hello"
let x = 5
send "AT+SET=$x\r\n"

Style B — mini-language with C-like blocks (variables, expressions, if/else, while, for):

let id = 3
let ok = 0

for (let i = 0; i < id; i++) {
    send "AT+PING\r\n"
    if (expect("PONG", 2000)) {
        ok++
    } else {
        log "device $i failed"
    }
    wait 200
}

if (ok == id) {
    log "all $id ok"
} else {
    log "$ok / $id ok"
}

Both styles can appear in the same script. Older scripts written for the simpler syntax keep working unchanged.

7.3 Commands — full reference

Sending data

  • send "text" — send a string (UTF-8). Escapes: \r \n \t \\ \" \' \0 \xNN.
  • send HEX "AA 55 01 FF" — legacy alias, sends raw hex bytes.
  • send[ENC] "text" — same as send, but encode with a specific encoding. Supported ENC:
    • Raw: HEX ("AA 55"), BIN ("10101010 01010101"), DEC ("170 85"), OCT ("252 125").
    • Text: UTF-8, ASCII, UTF-16LE, UTF-16BE, CP1251, CP1252, CP866, KOI8-R, Latin-1, Shift-JIS, GB2312, GBK.
  • send_slow[ENC] "text" ms — send one byte at a time with a delay of ms between bytes. Handy for slow MCU UARTs. Without [ENC], UTF-8 is used.

Waiting and matching

  • wait ms — pause for the given number of milliseconds.
  • expect "needle" ms — wait up to ms for needle to appear in RX. Only bytes received after the call are considered. Fails the script on timeout.
  • expect_search "needle" ms — same, but searches the whole RX buffer collected since the script started. Handy when the device sends a burst that already contains the needle before you started waiting.
  • assert_rx "needle" — check that needle is already somewhere in the RX buffer. Instant; no waiting.
  • In expression form (style B), expect(...), expect_search(...) and assert_rx(...) all return a boolean and never abort the script on failure. Use them inside if (...) for a soft check.

Variables and output

  • let name = value — define a variable. Value may be a number, a quoted string, or $other (a reference to another variable).
  • Inside any string, use $name to insert the value of a variable: send "AT+SET=$id\r\n".
  • log "text" — print a line to the terminal as [SCENARIO] text. Interpolates $var.
  • print expr — print the value of any expression.

Control flow (style B)

  • if (cond) { ... } else if (cond) { ... } else { ... }.
  • while (cond) { ... }.
  • for (init; cond; step) { ... }.
  • break / continue inside loops.

Operators (style B)

  • Arithmetic: + - * / %.
  • Comparison: == != < > <= >=.
  • Logic: && || ! (short-circuit).
  • Increment / decrement: x++, x--.
  • Compound assignment: += -= *= /= %=.

Built-in functions

expect("needle", ms) bool — see above.
expect_search("needle", ms) bool — see above.
assert_rx("needle") bool — instant check of the whole RX buffer.
num_from_rx(marker) int — read the first number that follows marker in the RX buffer. If marker is empty, returns the first number anywhere in the buffer. Returns 0 if no match. Fractional part is truncated (integers only).
len(s) int — length of a string.
num(s) int — parse a number; 0 if not numeric.
str(v) string — convert a value to text.
abs(n) int — absolute value.
time_ms() int — milliseconds since the script started.

7.4 A realistic example

# read temperature and toggle a fan
send "AT+READ\r\n"

if (expect("OK", 2000)) {
    let t = num_from_rx("TEMP=")
    log "temperature = $t"
    if (t > 30) {
        send "AT+FAN=1\r\n"
    } else {
        send "AT+FAN=0\r\n"
    }
} else {
    log "device did not respond"
}

7.5 Configuring slots

  • Setting → Configure macros → <tab> opens a dialog with 10 rows. Each row: text field + +CR + CR=CR+LF + HEX.
  • Buttons at the top:
    • Add scenario… — pick a .xyscen file and a slot number. The slot's button becomes S#.
    • Clear scenario — turn the slot back into a plain macro.
  • Setting → Reset all macros → … wipes macros for one prefix or all at once.
  • While a scenario is running, all macros and the input line are disabled. Progress is printed as [SCENARIO] … lines with their own color.

8. Triggers

Each tab can highlight substrings in the terminal output with custom foreground and background colors.

  • Setting → Configure triggers → <tab> opens a dialog.
  • Each row: text to match + foreground swatch + background swatch.
  • Matching is case-insensitive; earlier rows win on overlap.
  • Up to 50 triggers per tab.
  • Triggers are also saved in .xyrmc logs, so a browser renders the same highlight.
  • Setting → Reset triggers → <tab> / All wipes them.

9. Logs

  • Save log — write the current buffer to logs/ next to the app with an auto-generated name.
  • Save log as… — pick a path and format:
    • .xyrm — plain UTF-8 text.
    • .xyrmc — full HTML document with inline colors. Open it in any browser to see the terminal exactly as it was, including trigger highlights.
  • Open log… — open a previously saved log:
    • .xyrm — loaded into the current tab's terminal.
    • .xyrmc — opens a separate viewer window with a Play / Pause / Stop toolbar that replays the log with the original inter-line delays.
  • Open logs folder — opens logs/ in your file manager.

10. Settings menu reference

Theme Pick from 10 built-in palettes, follow the OS (System), or edit your own (Custom…). A random palette generator is also available under Random. Custom palettes are stored in QSettings.
Terminal text color Recolor each output category independently, or reset to the current theme. 16 named colors available. A color that is already used by another category is disabled to avoid clashes.
Language Switch the interface language on the fly. English, Russian, Belarusian, German, French, Chinese, Japanese, Korean.
UI scale 75% / 100% / 125% / 150%. Scales fonts, paddings, control sizes and the minimum window size. The choice is remembered.
Configure macros Edit the 10 macro slots per tab.
Reset all macros Wipe macros for one tab or all at once.
Configure triggers Edit the trigger list per tab.
Reset triggers Wipe triggers for one tab or all at once.
Transfer settings Chunk size / chunk delay / max file size for file transfer, plus “Remember last sent file path”.
Save format Plain text (.xyrm) or Colored HTML (.xyrmc).

11. View menu

  • Show or hide individual groups on the current tab (Connecting, Setting serial, Setting terminal, Server, Ping).
  • Show all — display every group of the current tab.
  • Hide all — hide every group of the current tab.

12. Keyboard shortcuts

  • Ctrl+F — search in terminal.
  • F3 / Shift+F3 — next / previous match.
  • Enter in Transmit input — send.
  • ↑ / ↓ in Transmit input — command history.
  • Esc — close search panel.

13. What gets remembered

On exit, the app stores window geometry, active tab, COM settings, TCP / UDP settings, ping settings, terminal toggles, transmit toggles, group visibility, theme (including the custom one and its palette), UI scale, language, terminal colors, save format, all macros and all triggers, plus the last sent file path when “Remember last sent file path” is enabled. Everything is restored on the next launch.

14. Themes overview

  • System — follows the OS color scheme (dark → Black, light → White).
  • Purple, Gray, White, Black, Beige — single-color palettes. Accents, tabs, buttons and highlights use the theme color; backgrounds are a dark shade of it. Red and green semantic buttons stay red and green regardless of theme.
  • Turquoise-Orange, Graphite-Sand, Purple-Gold, Coral-Mint, Navy-Crimson — two-color palettes. The background uses the first color; accents use the second.
  • Custom… — user-defined palette. Edit each of the 20 color roles with a color picker. Buttons:
    • Random — generates a harmonious random palette.
    • Reset to defaults — returns to the built-in Purple.
  • Random (in the menu) — instantly generates and applies a random custom palette.
