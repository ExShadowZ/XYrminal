XYrminal — guide utilisateur

XYrminal est un terminal multi-protocole pour dialoguer avec des appareils via série, TCP et UDP. Il fonctionne en client ou en serveur, transfère des fichiers, trace des graphiques en temps réel, exécute des macros et des scénarios, met en évidence des sous-chaînes avec des déclencheurs, et sauvegarde tout sur disque.

1. Vue des onglets

  • COM — port série (RS-232, RS-485, USB-CDC).
  • TCP Client — connexion à un serveur TCP distant.
  • TCP Server — écoute sur un port local, accepte de nombreux clients.
  • UDP Client — envoi/réception vers un host:port fixe.
  • UDP Server — bind d'un port local, réception de n'importe qui, diffusion.

2. Onglet COM

2.1 Connexion

  • Choisissez un port dans la liste ; appuyez sur Rechercher si la liste est obsolète.
  • Connecter ouvre le port, Déconnecter le ferme.
  • Quand le port est ouvert :
    • Les bascules DTR et RTS pilotent les deux lignes de sortie. DTR est généralement câblée sur la broche reset du MCU ; RTS sur BOOT0 ou une broche d'activation du bootloader. Un clic change la ligne sans rouvrir le port.
    • Quatre LED indiquent les lignes d'entrée : CD, RI, DSR, CTS. Vert = ligne active, éteint = inactive.

2.2 Paramètres série

Débit, bits de données, parité, bits d'arrêt, handshake. Chaque liste propose en bas une entrée Personnalisé… pour les valeurs non standard.

2.3 Paramètres du terminal

  • Défilement auto — saute en bas quand de nouvelles données arrivent.
  • Horodatage — préfixe [HH:MM:SS.mmm] devant chaque ligne.
  • Enreg. auto — la session courante est écrite dans un fichier au fur et à mesure.
  • Format — comment les octets entrants sont décodés :
    • Raw : HEX, DEC, OCT, BIN.
    • Texte : ASCII, UTF-8, UTF-16 LE, UTF-16 BE, CP1251, CP1252, CP866, KOI8-R, Latin-1, Shift-JIS, GB2312, GBK.
    En mode Raw, chaque bloc reçu est imprimé immédiatement sur une ligne à part. En mode Texte, les lignes partielles sont mises en tampon jusqu'à un saut de ligne ou 50 ms de silence — les données sans saut de ligne final sont tout de même affichées (flush style Hercules).
  • Graphique — ouvrir le panneau de graphique en direct (voir section 5).
  • Effacer — efface la vue du terminal.
  • Enregistrer le journal — déverse le tampon dans logs/.

2.4 Émission

  • Saisissez du texte, appuyez sur Entrée ou Envoyer. ↑ / ↓ — historique de saisie.
  • HEX — traiter la saisie comme des octets hex ("AA BB CC" → 3 octets). En mode HEX, +CR et CR=CR+LF sont ignorés.
  • +CR — ajouter un saut de ligne. Avec CR=CR+LF, cela devient CR+LF, sinon juste CR.
  • Macros — voir section 7.
  • Transfert de fichiers — voir section 6.

3. Onglets client TCP / UDP

  • Connexion — hôte / port distant, bind local optionnel, timeout.
  • Maintenir la connexion (TCP Client uniquement) — si le pair lâche le lien, le worker réessaie toutes les 2 secondes jusqu'à reconnexion ou appui sur « Déconnecter ».
  • Ping — sonde connect() TCP avec les mêmes statistiques que Test-Connection de PowerShell : Vérifier lance une série fixe, Démarrer lance un ping périodique, Arrêter l'arrête.

4. Onglets serveur TCP / UDP

  • TCP Server — écoute, liste des clients, Écho optionnel, Diffuser à tous optionnel, déconnecter un ou tous les pairs.
  • UDP Server — bind, réception de n'importe qui, mémorise le dernier expéditeur, répond au dernier / à une adresse explicite / diffuse en 255.255.255.255.
  • Les données entrantes sont préfixées par [host:port]. Les événements serveur ([+], [-], écoute, arrêt) ont une couleur dédiée.

5. Graphique en direct

Appuyez sur Graphique dans « Paramètres du terminal ». La zone terminale se scinde en deux : texte à gauche, graphique à droite.

  • Chaque ligne = une variable : Nom + Marqueur de parsing. Le nom est obligatoire ; le marqueur facultatif.
    • Avec marqueur (ex. VREF=) : le parser cherche le marqueur dans le texte entrant et lit le premier nombre après lui.
    • Sans marqueur : le parser lit le premier nombre n'importe où dans le bloc entrant.
  • Plusieurs lignes = plusieurs courbes sur le même graphique, chacune avec sa propre couleur.
  • Démarrer débute la capture. Pause / Reprendre fige la capture sans perdre de données. Arrêter termine la session et ferme le panneau.
  • T-Mode — l'axe X devient secondes écoulées au lieu de l'index d'échantillon. Le graphique défile en continu même sans nouvelles données.
  • View — combien de points (mode index) ou de secondes (T-Mode) sont affichés dans la fenêtre.
  • Export CSV — enregistrer tous les canaux capturés dans un fichier CSV compatible tableur : index,time_s,<canal1>,<canal2>,…. Les valeurs manquantes en fin de liste restent des cellules vides. UTF-8 avec BOM pour qu'Excel ouvre correctement les noms de canaux cyrilliques.
  • Survolez le graphique pour voir une info-bulle avec la valeur exacte.

6. Transfert de fichiers

  • Disponible dans les onglets COM, TCP Client et UDP Client.
  • Protocoles :
    • Raw — envoyer le fichier par blocs d'octets bruts avec un délai inter-blocs configurable. Idéal pour les bootloaders, images, configs.
    • XMODEM — blocs classiques de 128 octets avec CRC-16, handshake ACK/NAK, jusqu'à 10 tentatives par bloc.
    • YMODEM — XMODEM-1K avec un premier bloc « nom + taille ». Standard pour STM32 / ESP / AVR.
    • ZMODEM — pas encore implémenté.
  • La taille de bloc, le délai inter-blocs et la taille max du fichier se règlent dans Paramètres → Paramètres de transfert. On peut aussi y activer Mémoriser le dernier fichier envoyé pour restaurer le chemin et le protocole au prochain lancement.
  • XMODEM / YMODEM / ZMODEM ne sont pas disponibles via UDP.

7. Macros et scénarios

Chaque onglet a 10 slots, M1…M10. Chaque slot peut contenir soit une macro simple soit un script de scénario.

7.1 Macro simple

  • Court texte (ou octets hex) envoyé en un clic.
  • Chaque macro a ses propres drapeaux +CR, CR=CR+LF et HEX — indépendants de ceux au-dessus du champ de saisie.
  • Survolez un bouton pour voir son contenu. Les slots vides sont désactivés.

7.2 Script de scénario (.xyscen)

Un simple fichier texte UTF-8 avec une commande par ligne. Les commandes existent en deux styles, librement mélangeables dans le même fichier :

Style A — plat, une commande par ligne (syntaxe d'origine, toujours pleinement supportée) :

# commentaire
// aussi un commentaire
send "AT+RST\r\n"
send HEX "AA 55 01 FF"
wait 3000
expect "OK" 2000
expect_search "ERROR" 3000
assert_rx "READY"
log "bonjour"
let x = 5
send "AT+SET=$x\r\n"

Style B — mini-langage avec blocs de type C (variables, expressions, if/else, while, for) :

let id = 3
let ok = 0

for (let i = 0; i < id; i++) {
    send "AT+PING\r\n"
    if (expect("PONG", 2000)) {
        ok++
    } else {
        log "l'appareil $i n'a pas répondu"
    }
    wait 200
}

if (ok == id) {
    log "les $id ont répondu"
} else {
    log "$ok / $id ont répondu"
}

Les deux styles se mélangent. Les anciens scripts écrits dans la syntaxe d'origine continuent à fonctionner sans modification.

7.3 Référence complète des commandes

Envoi de données

  • send "texte" — envoyer une chaîne (UTF-8). Échappements : \r \n \t \\ \" \' \0 \xNN.
  • send HEX "AA 55 01 FF" — ancien alias, envoie des octets hex bruts.
  • send[ENC] "texte" — comme send, mais avec un encodage explicite. ENC supportés :
    • Raw : HEX ("AA 55"), BIN ("10101010 01010101"), DEC ("170 85"), OCT ("252 125").
    • Texte : UTF-8, ASCII, UTF-16LE, UTF-16BE, CP1251, CP1252, CP866, KOI8-R, Latin-1, Shift-JIS, GB2312, GBK.
  • send_slow[ENC] "texte" ms — envoyer octet par octet avec un délai de ms entre chaque. Utile pour les UART lents. Sans [ENC], utilise UTF-8.

Attente et vérification

  • wait ms — pause du nombre de millisecondes indiqué.
  • expect "texte" ms — attendre jusqu'à ms l'apparition de texte en RX. Seuls les octets reçus après l'appel sont considérés. Échec du script au timeout.
  • expect_search "texte" ms — idem, mais cherche dans tout le tampon RX accumulé depuis le lancement du script. Utile si l'appareil a déjà envoyé le texte avant l'attente.
  • assert_rx "texte" — vérifier que texte est déjà dans le tampon RX. Immédiat, sans attente.
  • En forme expression (style B), expect(...), expect_search(...) et assert_rx(...) renvoient un booléen et n'échouent pas le script. Idéal dans if (...).

Variables et sortie

  • let nom = valeur — définir une variable. Valeur : nombre, chaîne entre guillemets, ou $autre (référence).
  • Dans toute chaîne, $nom insère la valeur d'une variable : send "AT+SET=$id\r\n".
  • log "texte" — imprimer une ligne dans le terminal sous la forme [SCENARIO] texte. Interpole $var.
  • print expr — imprimer la valeur d'une expression quelconque.

Structures de contrôle (style B)

  • if (cond) { ... } else if (cond) { ... } else { ... }.
  • while (cond) { ... }.
  • for (init; cond; step) { ... }.
  • break / continue dans les boucles.

Opérateurs (style B)

  • Arithmétique : + - * / %.
  • Comparaison : == != < > <= >=.
  • Logique : && || ! (court-circuit).
  • Incrément / décrément : x++, x--.
  • Affectation composée : += -= *= /= %=.

Fonctions intégrées

expect("needle", ms) bool — voir ci-dessus.
expect_search("needle", ms) bool — voir ci-dessus.
assert_rx("needle") bool — vérification immédiate de tout le tampon RX.
num_from_rx(marker) int — premier nombre suivant marker dans le tampon RX. Marker vide → premier nombre dans tout le tampon. 0 si rien. Partie décimale tronquée (entiers seulement).
len(s) int — longueur d'une chaîne.
num(s) int — convertir en nombre ; 0 sinon.
str(v) string — convertir en texte.
abs(n) int — valeur absolue.
time_ms() int — millisecondes depuis le début du script.

7.4 Exemple réaliste

# lire la température et basculer un ventilateur
send "AT+READ\r\n"

if (expect("OK", 2000)) {
    let t = num_from_rx("TEMP=")
    log "température = $t"
    if (t > 30) {
        send "AT+FAN=1\r\n"
    } else {
        send "AT+FAN=0\r\n"
    }
} else {
    log "l'appareil n'a pas répondu"
}

7.5 Configuration des slots

  • Paramètres → Configurer les macros → <onglet> ouvre une boîte de dialogue avec 10 lignes : champ texte + +CR + CR=CR+LF + HEX.
  • Boutons en haut :
    • Ajouter un scénario… — choisir un fichier .xyscen et un numéro de slot. Le bouton du slot devient S#.
    • Supprimer le scénario — remettre le slot en mode macro simple.
  • Paramètres → Réinitialiser toutes les macros → … efface les macros d'un onglet ou de tous d'un coup.
  • Pendant qu'un scénario tourne, toutes les macros et la ligne de saisie sont désactivées. La progression est imprimée sous forme de lignes [SCENARIO] … dans leur propre couleur.

8. Déclencheurs

Chaque onglet peut surligner des sous-chaînes dans la sortie du terminal avec une couleur de texte et de fond personnalisées.

  • Paramètres → Configurer les déclencheurs → <onglet> ouvre une boîte de dialogue.
  • Chaque ligne : texte à rechercher + pastille de couleur de texte + pastille de couleur de fond.
  • Recherche insensible à la casse ; les lignes du haut gagnent en cas de chevauchement.
  • Jusqu'à 50 déclencheurs par onglet.
  • Les déclencheurs sont aussi enregistrés dans les journaux .xyrmc, pour qu'un navigateur affiche le même surlignage.
  • Paramètres → Réinitialiser les déclencheurs → <onglet> / Tous les efface.

9. Journaux

  • Enregistrer le journal — écrire le tampon courant dans logs/ à côté de l'app, avec un nom auto-généré.
  • Enregistrer le journal sous… — choisir un chemin et un format :
    • .xyrm — texte brut UTF-8.
    • .xyrmc — document HTML complet avec couleurs en ligne. Ouvrez-le dans n'importe quel navigateur pour voir le terminal exactement comme il était, y compris les surlignages de déclencheurs.
  • Ouvrir le journal… — ouvrir un journal déjà enregistré :
    • .xyrm — chargé dans le terminal de l'onglet courant.
    • .xyrmc — ouvre une fenêtre de visualisation séparée avec une barre Lecture / Pause / Arrêt qui rejoue le journal avec les délais entre lignes d'origine.
  • Ouvrir le dossier des journaux — ouvre logs/ dans votre gestionnaire de fichiers.

10. Menu Paramètres

Thème 10 palettes intégrées, « Système » (suit le schéma de l'OS), « Personnalisé… » (éditeur de palette) et « Aléatoire » (génération instantanée d'une palette aléatoire). Les palettes personnalisées sont stockées dans QSettings.
Couleur du texte du terminal Recolorer chaque catégorie de sortie indépendamment, ou réinitialiser au thème courant. 16 couleurs nommées. Une couleur déjà utilisée par une autre catégorie est désactivée pour éviter les conflits.
Langue Changer la langue de l'interface à chaud. Anglais, russe, biélorusse, allemand, français, chinois, japonais, coréen.
Échelle de l'interface 75 % / 100 % / 125 % / 150 %. Met à l'échelle les polices, les marges, la taille des contrôles et la taille minimale de la fenêtre. Le choix est mémorisé.
Configurer les macros Éditer les 10 slots de macro par onglet.
Réinitialiser toutes les macros Effacer les macros d'un onglet ou de tous d'un coup.
Configurer les déclencheurs Éditer la liste des déclencheurs par onglet.
Réinitialiser les déclencheurs Effacer les déclencheurs d'un onglet ou de tous.
Paramètres de transfert Taille de bloc / délai inter-blocs / taille max pour le transfert de fichiers, plus « Mémoriser le dernier fichier envoyé ».
Format d'enregistrement Texte brut (.xyrm) ou HTML coloré (.xyrmc).

11. Menu Affichage

  • Afficher ou masquer des groupes individuels de l'onglet courant (Connexion, Paramètres série, Paramètres du terminal, Serveur, Ping).
  • Tout afficher — afficher tous les groupes de l'onglet courant.
  • Tout masquer — masquer tous les groupes de l'onglet courant.

12. Raccourcis clavier

  • Ctrl+F — rechercher dans le terminal.
  • F3 / Shift+F3 — occurrence suivante / précédente.
  • Entrée dans le champ d'émission — envoyer.
  • ↑ / ↓ dans le champ d'émission — historique des commandes.
  • Échap — fermer le panneau de recherche.

13. Ce qui est mémorisé

À la fermeture, l'app enregistre la géométrie de la fenêtre, l'onglet actif, les paramètres COM, TCP / UDP, ping, les bascules du terminal et d'émission, la visibilité des groupes, le thème (y compris la palette personnalisée), l'échelle de l'interface, la langue, les couleurs du terminal, le format d'enregistrement, toutes les macros et tous les déclencheurs, plus le dernier chemin de fichier envoyé si l'option correspondante est activée. Tout est restauré au prochain lancement.

14. Aperçu des thèmes

  • Système — suit le schéma de couleurs de l'OS (sombre → Black, clair → White).
  • Purple, Gray, White, Black, Beige — palettes monochromes. Accents (onglets, boutons, titres de groupes, surlignages) utilisent la couleur du thème ; les arrière-plans en sont une teinte sombre. Les boutons sémantiques rouges et verts restent rouges et verts quel que soit le thème.
  • Turquoise-Orange, Graphite-Sand, Purple-Gold, Coral-Mint, Navy-Crimson — palettes bicolores. L'arrière-plan utilise la première couleur, les accents la seconde.
  • Personnalisé… — palette utilisateur. Chaque rôle parmi les 20 est éditable via un sélecteur de couleur. Boutons :
    • Random — génère une palette aléatoire harmonieuse.
    • Reset to defaults — revient au violet intégré.
  • Aléatoire (dans le menu) — génère et applique immédiatement une palette personnalisée aléatoire.
