XYrminal — руководство пользователя

XYrminal — мультипротокольный терминал для связи с устройствами по последовательному порту, TCP и UDP. Работает как клиент и как сервер, передаёт файлы, строит графики в реальном времени, выполняет макросы и сценарии, подсвечивает подстроки триггерами и сохраняет всё на диск.

1. Обзор вкладок

  • COM — последовательный порт (RS-232, RS-485, USB-CDC).
  • TCP Client — подключение к удалённому TCP-серверу.
  • TCP Server — прослушивание локального порта, много клиентов.
  • UDP Client — обмен с фиксированным host:port.
  • UDP Server — bind локального порта, приём от любого, broadcast.

2. Вкладка COM

2.1 Подключение

  • Выберите порт в списке; нажмите Сканировать, если список устарел.
  • Подключиться открывает порт, Отключиться — закрывает.
  • Когда порт открыт:
    • Тумблеры DTR и RTS управляют двумя выходными линиями. DTR обычно подключена к пину сброса МК, RTS — к BOOT0 или пину включения загрузчика. Щелчок переключает линию без переоткрытия порта.
    • Четыре LED-индикатора показывают входные линии: CD, RI, DSR, CTS. Зелёный = линия активна, тусклый = неактивна.

2.2 Настройки порта

Скорость, биты данных, чётность, стоп-биты, управление потоком. В каждом выпадающем списке внизу есть пункт Другое… — для нестандартных значений.

2.3 Настройки терминала

  • Автопрокрутка — перескок вниз при поступлении новых данных.
  • Метки времени — префикс [ЧЧ:ММ:СС.ммм] у каждой строки.
  • Автосохранение журнала — текущая сессия пишется в файл сразу по ходу работы.
  • Формат — как декодируются входящие байты:
    • Raw: HEX, DEC, OCT, BIN.
    • Текст: ASCII, UTF-8, UTF-16 LE, UTF-16 BE, CP1251, CP1252, CP866, KOI8-R, Latin-1, Shift-JIS, GB2312, GBK.
    В raw-режимах каждый принятый блок печатается сразу отдельной строкой. В текстовых строка копится до перевода строки или до 50 мс тишины — данные без «\n» на конце всё равно попадут на экран (Hercules-style flush).
  • График — открыть панель живого графика (см. раздел 5).
  • Очистить — стереть вывод терминала.
  • Сохранить журнал — выгрузить буфер в logs/.

2.4 Передача

  • Введите текст, нажмите Enter или Отправить. ↑ / ↓ — история ввода.
  • HEX — трактовать ввод как hex-байты ("AA BB CC" → 3 байта). В HEX-режиме +CR и CR=CR+LF игнорируются.
  • +CR — добавить конец строки. С CR=CR+LF будет CR+LF, иначе только CR.
  • Макросы — см. раздел 7.
  • Передача файлов — см. раздел 6.

3. Вкладки TCP / UDP клиента

  • Подключение — удалённый хост / порт, локальный bind, таймаут.
  • Держать соединение (только TCP Client) — при обрыве воркер каждые 2 секунды пытается подключиться заново, пока либо не получится, либо вы не нажмёте «Отключиться».
  • Пинг — серия TCP-проверок со статистикой, как Test-Connection в PowerShell: Проверить запускает фиксированную серию, Старт — периодический пинг, Стоп — останавливает.

4. Вкладки TCP / UDP сервера

  • TCP Server — слушать порт, список клиентов, опциональное Эхо, опциональный Broadcast всем, отключение одного или всех клиентов.
  • UDP Server — bind, приём от любого, запоминание последнего отправителя, ответ ему / явному адресу / broadcast.
  • Принятые данные помечаются префиксом [host:port]. События сервера имеют свой цвет.

5. Живой график

Нажмите График в «Настройках терминала». Область терминала делится пополам: слева текст, справа живой график.

  • Каждая строка = одна переменная: Имя + Маркер парсинга. Имя обязательно, маркер — нет.
    • С маркером (напр. VREF=): парсер ищет маркер во входящем тексте и берёт первое число после него.
    • Без маркера: берётся первое число во всём пришедшем блоке.
  • Несколько строк = несколько кривых на одном графике, каждая своим цветом.
  • Начать построение — начать сбор. Пауза / Продолжить — заморозить сбор без потери данных. Завершить построение — закончить сессию и закрыть панель.
  • T-Mode — ось X становится «секунд назад» вместо индекса точки. График прокручивается непрерывно даже без новых данных.
  • View — сколько точек (обычный режим) или секунд (T-Mode) влезает в окно.
  • Export CSV — сохранить все каналы в CSV-файл, удобный для Excel: index,time_s,<канал1>,<канал2>,…. Пропущенные значения остаются пустыми ячейками. Файл в UTF-8 с BOM, чтобы Excel корректно открыл русские имена каналов.
  • Наведите мышь на график — появится подсказка со значением.

6. Передача файлов

  • Доступна во вкладках COM, TCP Client, UDP Client.
  • Протоколы:
    • Raw — поток байт порциями с настраиваемой задержкой. Для загрузчиков, картинок, конфигов.
    • XMODEM — блоки по 128 байт, CRC-16, ACK/NAK, до 10 повторов на блок.
    • YMODEM — XMODEM-1K с первым блоком «имя + размер». Стандарт для STM32 / ESP / AVR.
    • ZMODEM — пока не реализован.
  • Размер блока, задержка и макс. размер файла — в Настройки → Настройки передачи. Там же можно включить Сохранять последний отправленный файл, чтобы путь и протокол восстанавливались при следующем запуске.
  • XMODEM / YMODEM / ZMODEM недоступны по UDP.

7. Макросы и сценарии

На каждой вкладке 10 слотов M1…M10. Каждый слот — либо обычный макрос, либо файл сценария.

7.1 Обычный макрос

  • Короткий текст (или hex-байты), отправляемый одним кликом.
  • У каждого макроса свои флаги +CR, CR=CR+LF, HEX — независимо от тумблеров над полем ввода.
  • Наведите на кнопку — увидите содержимое. Пустые слоты отключены.

7.2 Сценарий (.xyscen)

Обычный текстовый файл UTF-8, одна команда в строке. Команды бывают двух стилей, свободно смешиваемых в одном файле:

Стиль A — плоский, одна команда на строку (исходный синтаксис, полностью поддерживается):

# комментарий
// тоже комментарий
send "AT+RST\r\n"
send HEX "AA 55 01 FF"
wait 3000
expect "OK" 2000
expect_search "ERROR" 3000
assert_rx "READY"
log "привет"
let x = 5
send "AT+SET=$x\r\n"

Стиль B — мини-язык с блоками в стиле C (переменные, выражения, if/else, while, for):

let id = 3
let ok = 0

for (let i = 0; i < id; i++) {
    send "AT+PING\r\n"
    if (expect("PONG", 2000)) {
        ok++
    } else {
        log "устройство $i не ответило"
    }
    wait 200
}

if (ok == id) {
    log "все $id прошли"
} else {
    log "$ok / $id прошли"
}

Оба стиля можно смешивать в одном скрипте. Старые сценарии, написанные в исходном синтаксисе, продолжают работать без правок.

7.3 Полный справочник команд

Отправка данных

  • send "текст" — отправить строку (UTF-8). Экранирование: \r \n \t \\ \" \' \0 \xNN.
  • send HEX "AA 55 01 FF" — старый алиас, отправляет raw hex-байты.
  • send[ENC] "текст" — как send, но с явной кодировкой. Поддерживаются ENC:
    • Raw: HEX ("AA 55"), BIN ("10101010 01010101"), DEC ("170 85"), OCT ("252 125").
    • Текст: UTF-8, ASCII, UTF-16LE, UTF-16BE, CP1251, CP1252, CP866, KOI8-R, Latin-1, Shift-JIS, GB2312, GBK.
  • send_slow[ENC] "текст" ms — отправка побайтово с задержкой ms между байтами. Для медленных UART МК. Без [ENC] используется UTF-8.

Ожидание и проверка

  • wait ms — пауза на заданное число миллисекунд.
  • expect "текст" ms — ждать до ms появления текста в RX. Учитываются только байты, пришедшие после вызова. При таймауте сценарий падает.
  • expect_search "текст" ms — то же, но ищет во всём RX-буфере, накопленном с начала сценария. Полезно, когда устройство успело прислать пакет с нужным текстом ещё до начала ожидания.
  • assert_rx "текст" — проверить, что текст уже есть в RX-буфере. Мгновенно, без ожидания.
  • В форме выражения (стиль B) функции expect(...), expect_search(...) и assert_rx(...) возвращают булево значение и не валят сценарий при неудаче. Удобно использовать в if (...).

Переменные и вывод

  • let имя = значение — определить переменную. Значением может быть число, строка в кавычках или ссылка $другая.
  • Внутри любой строки можно подставить значение переменной через $имя: send "AT+SET=$id\r\n".
  • log "текст" — вывести строку в терминал как [SCENARIO] текст. Поддерживает $var.
  • print выражение — вывести значение любого выражения.

Управляющие конструкции (стиль B)

  • if (условие) { ... } else if (условие) { ... } else { ... }.
  • while (условие) { ... }.
  • for (инициализация; условие; шаг) { ... }.
  • break / continue внутри циклов.

Операторы (стиль B)

  • Арифметика: + - * / %.
  • Сравнение: == != < > <= >=.
  • Логика: && || ! (с коротким замыканием).
  • Инкремент / декремент: x++, x--.
  • Составные присваивания: += -= *= /= %=.

Встроенные функции

expect("текст", ms) bool — см. выше.
expect_search("текст", ms) bool — см. выше.
assert_rx("текст") bool — мгновенная проверка всего RX-буфера.
num_from_rx(маркер) int — первое число после маркера в RX-буфере. Если маркер пустой — первое число во всём буфере. Возвращает 0, если не найдено. Дробная часть отбрасывается (только целые).
len(s) int — длина строки.
num(s) int — разобрать число; 0, если не число.
str(v) строка — преобразовать значение в текст.
abs(n) int — абсолютное значение.
time_ms() int — миллисекунд с момента запуска сценария.

7.4 Реалистичный пример

# считываем температуру и переключаем вентилятор
send "AT+READ\r\n"

if (expect("OK", 2000)) {
    let t = num_from_rx("TEMP=")
    log "температура = $t"
    if (t > 30) {
        send "AT+FAN=1\r\n"
    } else {
        send "AT+FAN=0\r\n"
    }
} else {
    log "устройство не ответило"
}

7.5 Настройка слотов

  • Настройки → Настроить макросы → <вкладка> открывает диалог с 10 строками: текст + +CR + CR=CR+LF + HEX.
  • Кнопки сверху:
    • Добавить сценарий… — выбрать .xyscen и номер слота. Кнопка слота станет S#.
    • Убрать сценарий — вернуть слот в режим обычного макроса.
  • Настройки → Сбросить все макросы → … — стереть макросы одной вкладки или всех сразу.
  • Пока сценарий выполняется, все макросы и поле ввода заблокированы. Прогресс печатается строками [SCENARIO] … своим цветом.

8. Триггеры

Каждая вкладка может подсвечивать подстроки в выводе терминала заданным цветом текста и фона.

  • Настройки → Настроить триггеры → <вкладка>.
  • Каждая строка: текст + цвет текста + цвет фона.
  • Поиск без учёта регистра; при пересечении выигрывает верхняя строка.
  • До 50 триггеров на вкладку.
  • Триггеры сохраняются и в .xyrmc-логах — браузер рисует ту же подсветку.
  • Настройки → Сбросить триггеры → <вкладка> / Все.

9. Журналы

  • Сохранить журнал — выгрузить буфер в logs/ рядом с приложением, имя генерируется автоматически.
  • Сохранить журнал как… — выбрать путь и формат:
    • .xyrm — обычный текст UTF-8.
    • .xyrmc — полноценный HTML с инлайн-цветами, включая подсветку триггерами.
  • Открыть журнал… — открыть ранее сохранённый лог:
    • .xyrm — загружается в терминал текущей вкладки.
    • .xyrmc — отдельное окно-просмотрщик с панелью Запуск / Пауза / Стоп, проигрывающей лог с исходными задержками между строками.
  • Открыть папку журналов — открыть logs/ в файловом менеджере.

10. Меню «Настройки»

Тема 10 встроенных палитр, «Системная» (следует за темой ОС), «Пользовательская…» (свой редактор палитры) и «Случайная» (мгновенная генерация случайной палитры). Пользовательская палитра хранится в QSettings.
Цвет текста терминала Перекраска каждой категории вывода или сброс к текущей теме. 16 именованных цветов. Цвет, уже занятый другой категорией, отключается во избежание конфликта.
Язык Переключение языка интерфейса на лету. Английский, русский, белорусский, немецкий, французский, китайский, японский, корейский.
Масштаб системы 75% / 100% / 125% / 150%. Масштабирует шрифты, отступы, размеры элементов управления и минимальный размер окна. Выбор запоминается.
Настроить макросы Редактор 10 слотов на вкладку.
Сбросить все макросы Очистка макросов одной вкладки или всех.
Настроить триггеры Редактор триггеров на вкладку.
Сбросить триггеры Очистка триггеров одной вкладки или всех.
Настройки передачи Размер блока / задержка / макс. размер файла, плюс галочка «Сохранять последний отправленный файл».
Формат сохранения Обычный текст (.xyrm) или цветной HTML (.xyrmc).

11. Меню «Вид»

  • Показать или скрыть отдельные группы текущей вкладки (Подключение, Настройки порта, Настройки терминала, Сервер, Пинг).
  • Показать всё — показать все группы текущей вкладки.
  • Скрыть всё — скрыть все группы текущей вкладки.

12. Горячие клавиши

  • Ctrl+F — поиск в терминале.
  • F3 / Shift+F3 — следующее / предыдущее совпадение.
  • Enter в поле ввода — отправить.
  • ↑ / ↓ в поле ввода — история команд.
  • Esc — закрыть панель поиска.

13. Что запоминается

При выходе сохраняются: размер / позиция окна, активная вкладка, настройки COM, TCP / UDP, пинга, тумблеры терминала и передачи, видимость групп, тема (включая пользовательскую палитру), масштаб интерфейса, язык, цвета терминала, формат сохранения, все макросы и триггеры, а также последний отправленный файл, если включена соответствующая галочка. Всё восстанавливается при следующем запуске.

14. Обзор тем

  • Системная — следует цветовой схеме ОС (тёмная → Black, светлая → White).
  • Purple, Gray, White, Black, Beige — одноцветные палитры. Акценты (вкладки, кнопки, заголовки групп, выделения) — цвет темы, фон — его тёмный оттенок. Красные и зелёные семантические кнопки остаются красными и зелёными при любой теме.
  • Turquoise-Orange, Graphite-Sand, Purple-Gold, Coral-Mint, Navy-Crimson — двухцветные палитры. Фон — первый цвет, акценты — второй.
  • Пользовательская… — своя палитра. 20 цветовых ролей, каждая редактируется через палитру цветов. Кнопки:
    • Random — генерирует гармоничную случайную палитру.
    • Reset to defaults — сброс к встроенному фиолетовому.
  • Случайная (в меню) — мгновенно генерирует и применяет случайную пользовательскую палитру.
