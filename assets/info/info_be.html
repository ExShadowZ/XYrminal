XYrminal — кіраўніцтва карыстальніка

XYrminal — мультыпратакольны тэрмінал для сувязі з прыладамі па паслядоўным порце, TCP і UDP. Працуе як кліент і як сервер, перадае файлы, будуе графікі ў рэальным часе, выконвае макросы і сцэнары, падсвечвае падстрокі трыгерамі і захоўвае ўсё на дыск.

1. Агляд укладак

  • COM — паслядоўны порт (RS-232, RS-485, USB-CDC).
  • TCP Client — падключэнне да аддаленага TCP-сервера.
  • TCP Server — праслухоўванне лакальнага порта, шмат кліентаў.
  • UDP Client — абмен з фіксаваным host:port.
  • UDP Server — bind лакальнага порта, прыём ад любога, broadcast.

2. Укладка COM

2.1 Падключэнне

  • Выберыце порт у спісе; націсніце Сканіраваць, калі спіс састарэў.
  • Падключыцца адкрывае порт, Адключыцца — закрывае.
  • Калі порт адкрыты:
    • Тумблеры DTR і RTS кіруюць двума выходнымі лініямі. DTR звычайна падключана да піна скіду МК, RTS — да BOOT0 або піна ўключэння загрузчыка. Пстрычка перамыкае лінію без пераадкрыцця порта.
    • Чатыры LED-індыкатары паказваюць уваходныя лініі: CD, RI, DSR, CTS. Зялёны = лінія актыўная, цьмяны = неактыўная.

2.2 Налады порта

Хуткасць, біты даных, цотнасць, стоп-біты, кіраванне патокам. У кожным выпадаючым спісе ўнізе ёсць пункт Іншае… — для нестандартных значэнняў.

2.3 Налады тэрмінала

  • Аўтапрагортка — пераскок уніз пры паступленні новых даных.
  • Меткі часу — прэфікс [ГГ:ХХ:СС.ммм] у кожнага радка.
  • Аўтазахаванне журнала — бягучая сесія пішацца ў файл адразу па ходзе працы.
  • Фармат — як дэкадуюцца ўваходныя байты:
    • Raw: HEX, DEC, OCT, BIN.
    • Тэкст: ASCII, UTF-8, UTF-16 LE, UTF-16 BE, CP1251, CP1252, CP866, KOI8-R, Latin-1, Shift-JIS, GB2312, GBK.
    У raw-рэжымах кожны прыняты блок друкуецца адразу асобным радком. У тэкставых радок накопліваецца да пераносу радка або да 50 мс цішыні — даныя без «\n» на канцы ўсё роўна трапяць на экран (Hercules-style flush).
  • Графік — адкрыць панэль жывога графіка (гл. раздзел 5).
  • Ачысціць — сцерці вывад тэрмінала.
  • Захаваць журнал — выгрузіць буфер у logs/.

2.4 Перадача

  • Увядзіце тэкст, націсніце Enter або Адправіць. ↑ / ↓ — гісторыя ўводу.
  • HEX — трактаваць увод як hex-байты ("AA BB CC" → 3 байты). У HEX-рэжыме +CR і CR=CR+LF ігнаруюцца.
  • +CR — дадаць канец радка. З CR=CR+LF будзе CR+LF, інакш толькі CR.
  • Макросы — гл. раздзел 7.
  • Перадача файлаў — гл. раздзел 6.

3. Укладкі TCP / UDP кліента

  • Падключэнне — аддалены хост / порт, лакальны bind, тайм-аўт.
  • Трымаць злучэнне (толькі TCP Client) — пры абрыве воркер кожныя 2 секунды спрабуе падключыцца зноў, пакуль альбо не атрымаецца, альбо вы не націснеце «Адключыцца».
  • Пінг — серыя TCP-праверак са статыстыкай, як Test-Connection у PowerShell: Праверыць запускае фіксаваную серыю, Старт — перыядычны пінг, Стоп — спыняе.

4. Укладкі TCP / UDP сервера

  • TCP Server — слухаць порт, спіс кліентаў, апцыянальнае Рэха, апцыянальны Broadcast усім, адключэнне аднаго або ўсіх кліентаў.
  • UDP Server — bind, прыём ад любога, запамінанне апошняга адпраўніка, адказ яму / яўнаму адрасу / broadcast.
  • Прынятыя даныя пазначаюцца прэфіксам [host:port]. Падзеі сервера маюць свой колер.

5. Жывы графік

Націсніце Графік у «Наладах тэрмінала». Вобласць тэрмінала дзеліцца напалову: злева тэкст, справа жывы графік.

  • Кожны радок = адна зменная: Імя + Маркер парсінгу. Імя абавязковае, маркер — не.
    • З маркерам (напр. VREF=): парсер шукае маркер ва ўваходным тэксце і бярэ першы лік пасля яго.
    • Без маркера: бярэцца першы лік ва ўсім прыйшоўшым блоку.
  • Некалькі радкоў = некалькі крывых на адным графіку, кожная сваім цветам.
  • Пачаць пабудову — пачаць збор. Паўза / Працягнуць — замарозіць збор без страты даных. Завяршыць пабудову — скончыць сесію і закрыць панэль.
  • T-Mode — вось X становіцца «секунд таму» замест індэкса кропкі. Графік пракручваецца бесперапынна нават без новых даных.
  • View — колькі кропак (звычайны рэжым) або секунд (T-Mode) змяшчаецца ў акно.
  • Export CSV — захаваць усе каналы ў CSV-файл, зручны для Excel: index,time_s,<канал1>,<канал2>,…. Прапушчаныя значэнні застаюцца пустымі ячэйкамі. Файл у UTF-8 з BOM, каб Excel карэктна адкрыў рускія імёны каналаў.
  • Навядзіце мыш на графік — з'явіцца падказка са значэннем.

6. Перадача файлаў

  • Даступная ва ўкладках COM, TCP Client, UDP Client.
  • Пратаколы:
    • Raw — паток байт порцыямі з наладжвальнай затрымкай. Для загрузчыкаў, карцінак, канфігаў.
    • XMODEM — блокі па 128 байт, CRC-16, ACK/NAK, да 10 паўтораў на блок.
    • YMODEM — XMODEM-1K з першым блокам «імя + памер». Стандарт для STM32 / ESP / AVR.
    • ZMODEM — пакуль не рэалізаваны.
  • Памер блока, затрымка і макс. памер файла — у Налады → Налады перадачы. Там жа можна ўключыць Захоўваць апошні адпраўлены файл, каб шлях і пратакол аднаўляліся пры наступным запуску.
  • XMODEM / YMODEM / ZMODEM недаступныя па UDP.

7. Макросы і сцэнары

На кожнай укладцы 10 слотаў M1…M10. Кожны слот — альбо звычайны макрос, альбо файл сцэнара.

7.1 Звычайны макрос

  • Кароткі тэкст (або hex-байты), які адпраўляецца адным клікам.
  • У кожнага макроса свае флагі +CR, CR=CR+LF, HEX — незалежна ад тумблераў над полем уводу.
  • Навядзіце на кнопку — убачыце змесціва. Пустыя слоты адключаны.

7.2 Сцэнар (.xyscen)

Звычайны тэкставы файл UTF-8, адна каманда ў радку. Каманды бываюць двух стыляў, якія можна свабодна змешваць у адным файле:

Стыль A — плоскі, адна каманда на радок (зыходны сінтаксіс, поўнасцю падтрымліваецца):

# каментар
// таксама каментар
send "AT+RST\r\n"
send HEX "AA 55 01 FF"
wait 3000
expect "OK" 2000
expect_search "ERROR" 3000
assert_rx "READY"
log "прывітанне"
let x = 5
send "AT+SET=$x\r\n"

Стыль B — міні-мова з блокамі ў стылі C (зменныя, выразы, if/else, while, for):

let id = 3
let ok = 0

for (let i = 0; i < id; i++) {
    send "AT+PING\r\n"
    if (expect("PONG", 2000)) {
        ok++
    } else {
        log "прылада $i не адказала"
    }
    wait 200
}

if (ok == id) {
    log "усе $id прайшлі"
} else {
    log "$ok / $id прайшлі"
}

Абодва стылі можна змешваць у адным скрыпце. Старыя сцэнары, напісаныя ў зыходным сінтаксісе, працягваюць працаваць без правак.

7.3 Поўны даведнік каманд

Адпраўка даных

  • send "тэкст" — адправіць радок (UTF-8). Экранаванне: \r \n \t \\ \" \' \0 \xNN.
  • send HEX "AA 55 01 FF" — стары аляс, адпраўляе raw hex-байты.
  • send[ENC] "тэкст" — як send, але з яўнай кадаваннем. Падтрымліваюцца ENC:
    • Raw: HEX ("AA 55"), BIN ("10101010 01010101"), DEC ("170 85"), OCT ("252 125").
    • Тэкст: UTF-8, ASCII, UTF-16LE, UTF-16BE, CP1251, CP1252, CP866, KOI8-R, Latin-1, Shift-JIS, GB2312, GBK.
  • send_slow[ENC] "тэкст" ms — адпраўка пабайтава з затрымкай ms паміж байтамі. Для павольных UART МК. Без [ENC] выкарыстоўваецца UTF-8.

Чаканне і праверка

  • wait ms — пауза на зададзеную колькасць мілісекунд.
  • expect "тэкст" ms — чакаць да ms з'яўлення тэксту ў RX. Улічваюцца толькі байты, якія прыйшлі пасля выкліку. Пры тайм-аўце сцэнар падае.
  • expect_search "тэкст" ms — тое ж, але шукае ва ўсім RX-буферы, накопленым з пачатку сцэнара. Карысна, калі прылада паспела даслаць пакет з патрэбным тэкстам яшчэ да пачатку чакання.
  • assert_rx "тэкст" — праверыць, што тэкст ужо ёсць у RX-буферы. Імгненна, без чакання.
  • У форме выразу (стыль B) функцыі expect(...), expect_search(...) і assert_rx(...) вяртаюць булева значэнне і не валіць сцэнар пры няўдачы. Зручна ў if (...).

Зменныя і вывад

  • let імя = значэнне — вызначыць зменную. Значэннем можа быць лік, радок у двукоссі або спасылка $іншая.
  • Унутры любога радка можна падставіць значэнне зменнай праз $імя: send "AT+SET=$id\r\n".
  • log "тэкст" — вывесці радок у тэрмінал як [SCENARIO] тэкст. Падтрымлівае $var.
  • print выраз — вывесці значэнне любога выразу.

Кіруючыя канструкцыі (стыль B)

  • if (умова) { ... } else if (умова) { ... } else { ... }.
  • while (умова) { ... }.
  • for (ініцыялізацыя; умова; крок) { ... }.
  • break / continue унутры цыклаў.

Аператары (стыль B)

  • Арыфметыка: + - * / %.
  • Параўнанне: == != < > <= >=.
  • Логіка: && || ! (з кароткім замыканнем).
  • Інкрэмент / дэкрэмент: x++, x--.
  • Састаўныя прысваенні: += -= *= /= %=.

Убудаваныя функцыі

expect("тэкст", ms) bool — гл. вышэй.
expect_search("тэкст", ms) bool — гл. вышэй.
assert_rx("тэкст") bool — імгненная праверка ўсяго RX-буфера.
num_from_rx(маркер) int — першы лік пасля маркера ў RX-буферы. Калі маркер пусты — першы лік ва ўсім буферы. Вяртае 0, калі не знойдзена. Дробавая частка адкідаецца (толькі цэлыя).
len(s) int — даўжыня радка.
num(s) int — разабраць лік; 0, калі не лік.
str(v) радок — пераўтварыць значэнне ў тэкст.
abs(n) int — абсалютнае значэнне.
time_ms() int — мілісекунд з моманту запуску сцэнара.

7.4 Рэалістычны прыклад

# здымаем тэмпературу і перамыкаем вентылятар
send "AT+READ\r\n"

if (expect("OK", 2000)) {
    let t = num_from_rx("TEMP=")
    log "тэмпература = $t"
    if (t > 30) {
        send "AT+FAN=1\r\n"
    } else {
        send "AT+FAN=0\r\n"
    }
} else {
    log "прылада не адказала"
}

7.5 Налада слотаў

  • Налады → Наладзіць макросы → <укладка> адкрывае дыялог з 10 радкамі: тэкст + +CR + CR=CR+LF + HEX.
  • Кнопкі зверху:
    • Дадаць сцэнар… — выбраць .xyscen і нумар слота. Кнопка слота стане S#.
    • Прыбраць сцэнар — вярнуць слот у рэжым звычайнага макроса.
  • Налады → Скінуць усе макросы → … — сцерці макросы адной укладкі або ўсіх адразу.
  • Пакуль сцэнар выконваецца, усе макросы і поле ўводу заблакаваны. Прагрэс друкуецца радкамі [SCENARIO] … сваім цветам.

8. Трыгеры

Кожная ўкладка можа падсвечваць падстрокі ў вывадзе тэрмінала зададзеным цветам тэксту і фону.

  • Налады → Наладзіць трыгеры → <укладка>.
  • Кожны радок: тэкст + цвет тэксту + цвет фону.
  • Пошук без уліку рэгістра; пры перасячэнні перамагае верхні радок.
  • Да 50 трыгераў на ўкладку.
  • Трыгеры захоўваюцца і ў .xyrmc-логах — браўзер малюе тую ж падсветку.
  • Налады → Скінуць трыгеры → <укладка> / Усе.

9. Журналы

  • Захаваць журнал — выгрузіць буфер у logs/ побач з праграмай, імя генеруецца аўтаматычна.
  • Захаваць журнал як… — выбраць шлях і фармат:
    • .xyrm — звычайны тэкст UTF-8.
    • .xyrmc — паўнавартасны HTML з інлайн-колерамі, уключаючы падсветку трыгерамі.
  • Адкрыць журнал… — адкрыць раней захаваны лог:
    • .xyrm — загружаецца ў тэрмінал бягучай укладкі.
    • .xyrmc — асобнае акно-праглядальнік з панэллю Запуск / Пауза / Стоп, якая прайграе лог з зыходнымі затрымкамі паміж радкамі.
  • Адкрыць папку журналаў — адкрыць logs/ у файлавым менеджэры.

10. Меню «Налады»

Тэма 10 убудаваных палітраў, «Сістэмная» (сочыць за тэмай АС), «Карыстальніцкая…» (свой рэдактар палітры) і «Выпадковая» (імгненная генерацыя выпадковай палітры). Карыстальніцкая палітра захоўваецца ў QSettings.
Колер тэксту тэрмінала Перафарбоўка кожнай катэгорыі вываду або скід да бягучай тэмы. 16 іменаваных колераў. Колер, ужо заняты іншай катэгорыяй, адключаецца каб пазбегнуць канфлікту.
Мова Пераключэнне мовы інтэрфейсу на хаду. Англійская, руская, беларуская, нямецкая, французская, кітайская, японская, карэйская.
Маштаб сістэмы 75% / 100% / 125% / 150%. Маштабуе шрыфты, водступы, памеры элементаў кіравання і мінімальны памер акна. Выбар запомніцца.
Наладзіць макросы Рэдактар 10 слотаў на ўкладку.
Скінуць усе макросы Ачыстка макросаў адной укладкі або ўсіх.
Наладзіць трыгеры Рэдактар трыгераў на ўкладку.
Скінуць трыгеры Ачыстка трыгераў адной укладкі або ўсіх.
Налады перадачы Памер блока / затрымка / макс. памер файла, плюс галачка «Захоўваць апошні адпраўлены файл».
Фармат захавання Звычайны тэкст (.xyrm) або каляровы HTML (.xyrmc).

11. Меню «Выгляд»

  • Паказаць або схаваць асобныя групы бягучай укладкі (Падключэнне, Налады порта, Налады тэрмінала, Сервер, Пінг).
  • Паказаць усё — паказаць усе групы бягучай укладкі.
  • Схаваць усё — схаваць усе групы бягучай укладкі.

12. Гарачыя клавішы

  • Ctrl+F — пошук у тэрмінале.
  • F3 / Shift+F3 — наступнае / папярэдняе супадзенне.
  • Enter у полі ўводу — адправіць.
  • ↑ / ↓ у полі ўводу — гісторыя каманд.
  • Esc — закрыць панэль пошуку.

13. Што запомніцца

Пры выхадзе захоўваюцца: памер / пазіцыя акна, актыўная ўкладка, налады COM, TCP / UDP, пінгу, тумблеры тэрмінала і перадачы, бачнасць груп, тэма (уключаючы карыстальніцкую палітру), маштаб інтэрфейсу, мова, колеры тэрмінала, фармат захавання, усе макросы і трыгеры, а таксама апошні адпраўлены файл, калі ўключана адпаведная галачка. Усё аднаўляецца пры наступным запуску.

14. Агляд тэм

  • Сістэмная — сочыць за колеравой схемай АС (цёмная → Black, светлая → White).
  • Purple, Gray, White, Black, Beige — аднаколерныя палітры. Акцэнты (укладкі, кнопкі, загалоўкі груп, вылучэнні) — колер тэмы, фон — яго цёмны адценак. Чырвоныя і зялёныя семантычныя кнопкі застаюцца чырвонымі і зялёнымі пры любой тэме.
  • Turquoise-Orange, Graphite-Sand, Purple-Gold, Coral-Mint, Navy-Crimson — двухколерныя палітры. Фон — першы колер, акцэнты — другі.
  • Карыстальніцкая… — свая палітра. 20 колеравых роляў, кожная рэдагуецца праз палітру колераў. Кнопкі:
    • Random — генеруе гарманічную выпадковую палітру.
    • Reset to defaults — скід да ўбудаванага фіялетавага.
  • Выпадковая (у меню) — імгненна генеруе і ўжывае выпадковую карыстальніцкую палітру.
